# 相机标定引入规划

日期：2026-10-16。

对象：把相机**内参 + 畸变**标定接进本工程——做成一个**独立的标定线程**（`TRD_CALIB`）。它和识别线程 `TRD_VISION` 都是相机帧的消费者，但**两者互斥**（都往 `vision_to` 发，同时开会互相覆盖）：标定订阅相机线程发布的 `camera_to`，在帧上画出认出来的圆心再发到 `vision_to`，按快门采满样本后解出内参、把键值逐行打印。显示线程 `TRD_DISPLAY` 只订 `vision_to`，由这两个中的任一个拉起。

状态：只做规划。本工程当前没有任何标定代码、没有内参/畸变，`ArmorDetector` 只输出二维检测；`README` 里"PnP/距离估计尚未接入"说的就是这件事。

**由这些数字算出来的量（阈值和验收线都从它们来）：**

- 板物理尺寸：宽 `(9−1)×40 = 320 mm`、高 `(6−1)×40 = 200 mm`。板占画面宽的比例 `f·W/(d·1440)`，在 1440 宽上是 `578.8/(d·1440)`：`d = 0.5 m` 时 80%、`d = 1.0 m` 时 40%。**工作距离定 0.5–1.0 m**。
- 1 像素在 f=1808.83 px 下是 `1/1808.83 = 5.53e-4 rad = 0.0317°`，3 m 处折合 **1.66 mm**；参考的 0.0595 px 在 1.26 m 处是 41 µm。
- 主点偏移 `(713.705−720, 566.093−540) = (−6.30, +26.09) px`；`26.09/1808.04 = 0.0144 rad = 0.83°` 等效视轴偏角 → **不能拿图像几何中心当主点**（3 m 处偏 43 mm）。
- 角点畸变：对角处 `r/f = √(720²+540²)/1808.83 = 0.498`，`Δr/r = k1r² + k2r⁴ = −1.81% + 0.89% = −0.92%` → k1 与 k2 在画面角点互相抵消掉一半，**必须把全部系数解出来**。
- 视场角 `2·atan(720/1808.83) = 43.4°`（水平）、`33.3°`（垂直）→ 视场窄，沿用参考固定 k3。3 m 处 0.92% 的径向偏差折合 13.7 mm。
- 样本冗余：每幅 54 个点 = 108 个方程；9 幅共 972 个方程对 `8 + 6×9 = 62` 个未知量（15.7:1）。
- 样本点内存：9×54×2 个 float = **3.8 KB**；圆心留在内存里求解，合格样本的整幅图另外存成 jpg。

**病灶（每条都是上面数字算出来的）：**

- 没有内参：主点用几何中心就带 0.83° 等效视轴偏角，3 m 处横向偏 43 mm。
- 没有畸变：画面角点处径向偏差 0.92%，3 m 处 13.7 mm——两者都远大于角点本身的像素噪声。
- 构建侧：根 CMake 不找 `calib3d`，算法层没有任何标定代码。
- 采集侧：参考的样本目录在本仓库不存在，样本只能在线上采。

关键点：**标定与识别都消费 `camera_to`，但互斥**——两者都往 `vision_to` 发，同开会互相覆盖，所以 Kconfig 里各写 `depends on !对方`；显示侧不区分来源。标定取帧后把圆心画在 clone 出来的副本上再 `Publish`，所以标定那一版屏幕上就是带圆心标记的画面，而显示线程仍是纯转发。

**采样节奏由 shell 快门决定**：操作者摆好板再按 `var set calib.capture 1`，标定只判这一帧合不合格——识别出完整点阵、与已保留样本够不同、距上次保留够间隔；不合格的打一行说明原因、丢掉、不占样本位，要重试就再按一次。快门与清零共用一把锁，一次按键只被消费一次。

**画面：标定画、显示转发。** 标定线程不自己开窗口——它把**每个认出来的圆心套一个圈**（半径 8 px）画在发布帧上，圈按行换色（行序或列序要是反了（转置），颜色分布会立刻不对），显示线程照旧只 `imshow`。这样一来"显示不做图像处理"这条约束不用破，标定也拿得到它要的实时反馈。画在 clone 出来的副本上——通道里的像素与显示侧共享，约定要求改图的一方自己复制。

## 4. Kconfig 与构建开关

`project/Kconfig`（`TRD_CALIB` 分区，位置照 `TRD_CAMERA`；分区顺序按数据流排）：

```kconfig
config TRD_CALIB
    bool "Camera intrinsic calibration thread"
    default y
    depends on TRD_CAMERA && !TRD_VISION
    select DUST_CALIB
    select DUST_TPC_CAMERA_TO
    select DUST_TPC_VISION_TO
    help
      启动期内参标定线程：订阅 camera_to，把认出来的圆心画在帧上转发到
      vision_to，按 shell 快门保留合格样本，收满后解出内参并逐行打印。
      与 TRD_VISION 互斥——两者都往 vision_to 发，同时开会互相覆盖。
```

两条依赖各有原因：`depends on TRD_CAMERA` 是因为帧从它来，`&& !TRD_VISION` 是因为两者共用 `vision_to` 这条出口。`TRD_VISION` 对称地写 `depends on TRD_CAMERA && !TRD_CALIB`——两边都写是为了让结果与符号出现顺序无关。`TRD_DISPLAY` 上游改成 `depends on (TRD_VISION || TRD_CALIB)`：只开标定那一版时显示线程仍要起来，否则标定过程看不到画面。

`framework/algorithm/Kconfig`：

```kconfig
config DUST_CALIB
    bool "circle-grid camera calibration"
    default n
    help
      Planar circle-grid intrinsic solver and reprojection check (algorithm/calib).
```

门禁归属照现有规矩：架构层建库与 `find_package` 跟 `CONFIG_DUST_CALIB`；业务线程源文件与链接跟 `CONFIG_TRD_CALIB`（同 `TRD_VISION` → `DUST_VISION_YOLO` 那一对）。开关关闭时标定代码一个字节都不进 `vision_app`，也不找 `calib3d`。

## 5. 算法与公式

**物点**（mm）：`{(j·d, i·d, 0)}`，`d = center_distance_mm`，`i ∈ [0, rows)`、`j ∈ [0, cols)`，行优先，顺序与 `findCirclesGrid` 返回的圆心顺序一致。

**识别**：`cv::findCirclesGrid(bgr, {cols, rows}, centers, cv::CALIB_CB_SYMMETRIC_GRID)`，成功得 54 个原图像素坐标；失败该帧丢弃、不计入样本数（照 `capture.cpp:156-195`）。每帧都跑一次：结果既用来画预览，也是快门判合格的第 1 道。

**样本签名**（从当帧 54 个圆心算出的纯几何量，用于快门合格判定）：四角圆心索引为 `0`(左上)、`cols−1`(右上)、`cols·rows−1`(右下)、`cols·(rows−1)`(左下)。

- 板心 `c` = 圆心均值（px）
- 尺度 `s` = 四角四边形四条边的平均长度（px），`s ∝ 1/距离`
- 俯仰比 `p` = 上边边长 / 下边边长
- 偏航比 `y` = 左边边长 / 右边边长

**合格判据**：一次快门（`var set calib.capture 1`）对应一帧，这一帧要依次过四道，任一道不过就丢掉、不占样本位：

1. 识别出完整 54 个圆心（`findCirclesGrid` 成功）；
2. 签名可算（四角边不退化）；
3. 对**每个**已保留样本都要满足下列之一；
4. 距上次保留 ≥ `sample_interval_ms`。

```text
|c_new − c_old| ≥ min_shift_px
|s_new − s_old| / max(s_new, s_old) ≥ min_scale_change
|p_new − p_old| ≥ min_ratio_change
|y_new − y_old| ≥ min_ratio_change
```

门限的物理含义（在 0.7 m、板宽 320 mm 下）：`80 px ≈ 横向 31 mm`；`15% 尺度 ≈ 前后 91 mm`；`0.10 的边比 ≈ 偏转 12°`（`(d+a)/(d−a) = 1.10`，`a = 0.16·sinθ`）。合格样本的整幅图写进 `samples_dir`，文件名按保留序号从 `1.jpg` 起。

**求解**（照参考）：

```cpp
cv::calibrateCamera(object_points, image_points, {1440, 1080}, K, dist, rvecs, tvecs,
                    cv::CALIB_FIX_K3,
                    cv::TermCriteria(cv::TermCriteria::COUNT + cv::TermCriteria::EPS, 100, DBL_EPSILON));
```

视场窄（43.4°）不需要 k3，固定为 0；默认 30 次迭代在参考那里会发散，提到 100（照参考注释）。

**重投影误差**：逐样本 `cv::projectPoints(obj_points[i], rvecs[i], tvecs[i], K, dist, reprojected)`，`error = Σ‖img_points[i][j] − reprojected[j]‖ / Σ点数`（px）。用显式 `projectPoints` 而不是 `calibrateCamera` 的返回值——口径与参考一致，便于对照。

**单位**：物点用 mm，解出的 `tvec` 也是 mm；**内参与畸变是无量纲/像素量，不做 mm→m 换算**（参考只在手眼外参那里除过 1e3，这里没有那一步）。

**求解后的验收检查**（不过就判失败、不写文件、启动中止）：

1. `reprojection_error ≤ max_reprojection_error_px`
2. `|fx/fy − 1| ≤ 0.01`——像素应为方形；参考 `1808.830/1808.041 = 1.00044`
3. `|cx − W/2| ≤ 0.05·W` 且 `|cy − H/2| ≤ 0.05·H`——主点应接近几何中心；参考偏移 `26.09 px = 0.024·H`

**产物格式**：写成**标量键**，不是参考的 9 元序列。原因是本工程的 `cmd::config::Config` 只读标量（`GetInt/GetDouble/GetBool/GetString/GetPath`，见 `framework/cmd/config/config.hpp:34-38`），写成序列就得给它新加一个数组读取入口；写成标量则读入侧一行代码都不用加。分辨率也会变，所以把图像尺寸一起写进文件，读入侧可以据此判废。

```yaml
# 12 个键，粘到 thread/calib/trd_calib.yaml 末尾。下面是本机 2026-10-16 标出来的值。
image_width: 1440
image_height: 1080
camera_fx: 1803.947
camera_fy: 1804.374
camera_cx: 722.632
camera_cy: 503.656
distort_k1: -0.076562
distort_k2: 0.139583
distort_p1: -0.000504
distort_p2: 0.000944
distort_k3: 0
reprojection_error_px: 0.0694
```

`sample_count` 不在这 12 个里：它是输入项，配置文件里本来就有，重复写会让 `Config` 判成重复键。

**读入**：产物那 12 个键住在**视觉线程**的 `thread/vision/trd_vision.yaml`，是 `Config::Load` 的**可选**字段（与精修参数同一张表）；`trd_vision.cpp` 的 `LoadVisionConfig()` 在 `thread_init` 里读入并在日志打一行 `vision: intrinsics 1440x1080 fx=… fy=… cx=… cy=…`。标定组件本身不读它——标定只管产出，内参与畸变只有视觉处理（PnP）要读。

**输出**：程序不写文件——标定完把 12 个键按配置里的键名逐行打印，人粘回 `thread/calib/trd_calib.yaml` 并去掉行首的注释符号。后续 PnP 从同一份文件读同一批键，不新增数组读取入口。

**打印**：单条日志在彩色模式下只有约 101 字节可用（`kTxFrameSize − 1 − 前缀 − 行尾`），所以每一类各占一行，不往一行里堆：

```text
[inf] calib: board 9x6 center_distance=40.0mm target=9 samples
[inf] calib: press the shutter with `var set calib.capture 1`
[ok]  calib: circle grid detected, 54 centers                            # 第一次认出点阵时报一次
[wrn] calib: shot dropped: pose repeats a kept sample                    # 快门不合格：逐条给原因
[inf] calib: waiting samples=4/9 shots=3 detected=yes                    # 每 5 s 一行
[inf] calib: sample 6/9 center=(812,540) span=459px pitch=1.02 yaw=1.18 -> 6.jpg
[inf] calib: image_width: 1440                                           # 收满 9 张、验收通过后按配置的键名逐行打印 12 个键
[inf] calib: camera_fx: 1803.947                                         # 每行形如 "calib: <键>: <值>"，直接往配置里抄
        …（image_height / camera_fy / camera_cx / camera_cy / distort_k1 / distort_k2 /
           distort_p1 / distort_p2 / distort_k3 / reprojection_error_px）
[ok]  calib: paste the keys above into thread/vision/trd_vision.yaml
```

不合格的四条原因各有一句 `shot dropped: …`（没识别到 / 点阵退化 / 姿态重复 / 间隔太短），按键没反应时日志会直接说出是哪一条。`waiting` 那一行报保留了几张、本周期按了几次快门、以及这一帧有没有认出点阵：**一直 `detected=no` 就是板压根没被认出来**（先查板规格与画面朝向），不是快门的问题。验收不过会 `System_RequestStop(1)` 直接停进程——那批样本解不出可信内参，继续转着也没意义。

## 7. 分步骤

### 阶段 1：算法层

**做什么 / 落点：** `framework/algorithm/calib/camera_calib.hpp/.cpp`（板规格、识别、样本签名、接受判据、求解、重投影误差）；`framework/algorithm/Kconfig` 加 `DUST_CALIB`；`framework/CMakeLists.txt` 建 `framework_calib`；根 `CMakeLists.txt` 条件找 `calib3d`；合成自检放 test 线程 `project/thread/test/trd_test.cpp` 的 `CheckCalibration()`，由 `TRD_TEST` 开关拉起（`project/Kconfig` 加 `select DUST_CALIB`，`project/CMakeLists.txt` 链 `framework_calib`）。

**验收数字：** `CONFIG_DUST_CALIB=y` 时 `framework_calib` 建成并链上 `libopencv_calib3d.so.4.6.0`；`=n` 时 `vision_app` 的链接行里不出现 `calib3d`（只做静态检查，不额外跑构建）。数值正确性由合成自检给出：`TRD_TEST=y` 启动时 `test_init` 按六组板姿态用 `projectPoints` 造圆心，再喂给 `SolveIntrinsics`，反解的内参矩阵、畸变系数与重投影误差三项都 < 1e-3（矩阵项按 `max(|期望|, 1)` 归一）。圆心存成 float，量化台阶约 1e-4 px，误差地板在 1e-6 量级，所以 1e-3 只用来抓点序/单位/flag 写错那类量级 1e-1 的错，不是精度指标——**实测值以日志里 `calib selfcheck` 那两行为准**。

**失败分叉：** 找不到 `calib3d` → 先确认 `find_package` 的组件名与 `DUST_CALIB` 是否打开，不去改算法层；自检反解偏差到 1e-1 量级 → 先查物点顺序与单位（mm 当成了米），再查 `CALIB_FIX_K3` 与迭代次数。

### 阶段 2：标定组件与装配

**做什么 / 落点：** `project/thread/calib/trd_calib.cpp`（订阅 `camera_to` → 画圆心并发 `vision_to` → 按快门判合格 → 求解 → 打印键值 → 存样本图）、`trd_calib.yaml`、`project/Kconfig` 的 `TRD_CALIB`、`project/thread/CMakeLists.txt`（`project/CMakeLists.txt` 里 `framework_calib` 的链接已在阶段 1 加上）。另外 `project/thread/vision/trd_vision.yaml` 加那 12 个键、`trd_vision.cpp` 的 `LoadVisionConfig()` 读入它们。

**验收数字：** 实机把板放在 0.5–1.0 m，标定期间显示窗口有实时画面、识别到点阵时画出圆心；按 9 次快门（每次都是合格帧）后求解；合格样本落在 `<配置根>/calibration_samples/1.jpg…9.jpg`；日志按 §5 各打一行；重投影误差 ≤ 0.3 px；`|fx/fy − 1| ≤ 0.01`；主点在画面几何中心 ±5% 内；那 12 个键按配置里的键名逐行打印出来。不合格的快门要能各打出对应原因且不占样本位；采集期间 Ctrl+C 能在 1 s 内中止（循环里查停止标志，不闷等）；关闭 `TRD_CALIB` 重新构建后 `vision_app` 行为与现在完全一致。

**失败分叉：** 见 §9。

### 阶段 3：视觉侧读入（已并入阶段 2）

**做什么：** 那 12 个键在 `trd_vision.yaml` 里是**可选**字段；`trd_vision.cpp` 的 `LoadVisionConfig()` 在 `thread_init` 里读入并存进 `CameraIntrinsics`，随后打一行 `vision: intrinsics 1440x1080 fx=… fy=… cx=… cy=…`。读法就是 `Config::Load` 的必选/可选两张字段表，`Config` 对未知键、重复键、缺键都直接报错，所以这一步同时验证了产物键集合与严格校验一致。

**验收数字：** `trd_vision.yaml` 里粘好那 12 个键后启动视觉线程，日志出上面那行且检测链行为不变；键缺一个或数值越界时 `Config` 直接报错。

**失败分叉：** 报 unknown key / required key / duplicate key → 改产物键集合，不去放宽 `Config` 的校验；报数值越界 → 检查 `LoadVisionConfig()` 里各字段的范围上限。

## 8. 顺序为什么不能换

1. **算法层必须先于组件**：标定组件只负责开相机、取帧、编排与落盘；求解逻辑留在算法层，才能离线复算、才不被相机绑住。
2. **标定的 init/thread 与识别同阶段（`AppInit`/`AppThread`）**：两者都订阅相机帧，顺序上没有前后依赖；相机帧在 `EarlyThread` 就已经在发布了，所以到 `AppInit` 时 `camera_to` 里一定有数据。显示回调由 `AppInit` 注册，等 `AppThread` 跑完才开始转，那时两个发布方都已经在出帧。
3. **`calib3d` 依赖必须跟 `DUST_CALIB` 走**：不打开这个能力时根 CMake 不找 `calib3d`，否则"只有检测"的最小构建被无谓拉上标定依赖。
4. **产物格式必须先冻结**：读入侧、将来的 PnP 都按这份键集合写；格式一变，之前标出来的文件全作废。
5. **采集门限必须先冻结**：样本口径一变，之前所有误差数字不可比。

## 9. 失败回退表

| 症状 | 先查 | 再查 | 最后才查 |
| --- | --- | --- | --- |
| `findCirclesGrid` 一直失败 | `pattern_cols/rows/center_distance_mm` 是否与实际板子一致 | 板是否完整入画、是否过曝/欠曝、距离是否在 0.5–1.0 m | 是否该换非对称图案 |
| 收不到 `sample_count` 个样本 | 三个去重门限是否太严、板是否真的移动过 | 板是否始终完整在画面内 | 是否下调 `sample_count` |
| 重投影误差 > 0.3 px | 是否混进了运动模糊样本（板没停稳） | 板是否平整/反光、是不是少数样本特别差 | 迭代次数与 `CALIB_FIX_K3` |
| fx/fy 偏离 1 超过 1%，或主点跑出中心 5% | 样本是否只有平移、没有倾斜 | 分辨率/像素是否被 SDK 缩放过——与 `image_width/height` 对不对得上 | 是否提高 `sample_count` 或换标定板 |
| 采集到时限还没凑满 | 快门有没有被收到（`shots` 涨不涨） | 三个去重门限是否太严、板是否真的移动过 | `capture_timeout_s` 是否够摆完一轮 |
| 画面全黑/全无帧 | `TRD_CAMERA` 有没有开（标定与识别都靠它出帧） | 曝光够不够看清板 | 显示窗口是不是被 `display.show` 关了 |
| 启动被中止 | `TRD_CAMERA` 没开、或 `TRD_VISION` 没关（两者互斥） | 相机没就绪、`HaltOnFail` 是设计行为不是崩溃 | 日志里的 `calib:` 失败行 |
| 视觉读不到内参 | 12 个键有没有从日志粘进 `thread/vision/trd_vision.yaml` | 键是否齐全、数值是否越界 | `Config` 报的 unknown / required key 具体指哪个键 |

## 10. 明确不做

1. 不做手眼外参（`R_camera2gimbal` / `t_camera2gimbal`）：本工程没有云台/IMU 设备层，样本里的四元数无从取得。
2. 不做按键采集（参考那套在窗口里按 `s` 存图），也不接 Foxglove 预览与触发；标定不开自己的窗口——圆心画进发布帧，由显示线程转发，快门走 `calib.capture`。
3. 不做离线样本目录工具（参考的 `calibrate_*.cpp` 那类独立可执行）：本工程标定在启动期完成。
4. 不引入 `fmt`、`nlohmann::json` 依赖（用 `DUST_LOG` 和 yaml-cpp）。
5. 不在本次规划内接 PnP、跟踪或云台控制；配置里的产物段只是为它们准备好输入。
6. 不改 `trd_vision.yaml` 现有字段，不改检测链。

## 11. 完成定义

- `TRD_CAMERA=y` + `TRD_CALIB=y` + `TRD_VISION=n` 时，相机、标定、显示三个线程起来：显示窗口里是带圆心标记的实时画面；按 9 次快门后解出内参与畸变，那 12 个键按 §5 逐行打印出来。
- `TRD_CALIB` 与 `TRD_VISION` 互斥（各自 `depends on TRD_CAMERA && !对方`），选不出同时打开的组合；`TRD_DISPLAY` 在只开标定那一版时照样起来（`(TRD_VISION || TRD_CALIB)`）。
- 采集超时、样本不足、重投影误差超限、fx/fy 与主点越界——任一条不过就 `System_RequestStop(1)` 停进程。
- 标定组件不写任何配置文件：产物靠人从日志粘。`trd_calib.yaml` 因此照常留在构建期复制列表里——`dust build` 复制它也不会把标定结果弄丢。
- 视觉线程从 `trd_vision.yaml` 读出那 12 个键（键集合与 `cmd::config::Config` 的严格校验一致），在 `thread_init` 里打一行 `vision: intrinsics …`。
- `TRD_CALIB=n` 时标定代码一字节不进 `vision_app`，根 CMake 不找 `calib3d`，运行行为与现在完全一致。
- 标定期间 Ctrl+C 能及时中止，不阻塞退出流程。
