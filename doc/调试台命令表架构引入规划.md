# 调试台命令表架构引入规划

日期：2026-10-22。

对象：当前 Linux 视觉工程 `framework/cmd/shell/` 的**命令解析与分派**——把 `shell.cpp` 里手写的 if-else 命令链，换成分层参考（`temp/Dust_Zephyr_Tree/framework/cmd/shell/`）的「行切分（token）+ 链接段注册 + 线性查表分派 + 帮助自动生成」。

状态：当前 3 个命令族（`log` / `var` / `h`）的名字、分派和帮助分散在 `shell.cpp` 的两处（分派链、`CmdHelp`），每族参数解析各写一套（`log.cpp` 与 `var.cpp` 各一个 `std::istringstream`）。日志系统、`var` 的注册表本身不动。

本规划含**两件互不依赖的事**：A（§5–§10）命令表架构；B（§11）输入行历史 + 上下方向键切换。两者都只改 `shell.hpp` / `shell.cpp`，可以分开做、分开验收。

参考：[shell.cpp](../temp/Dust_Zephyr_Tree/framework/shell/shell.cpp)、[shell_cmd.hpp](../temp/Dust_Zephyr_Tree/framework/shell/shell_cmd.hpp)、[token.hpp](../temp/Dust_Zephyr_Tree/framework/shell/token.hpp)、[var/var.cpp](../temp/Dust_Zephyr_Tree/framework/shell/var/var.cpp)。

## 1. 依据来源与边界

**取自参考：**

- 行切分：`SkipSpace` / `NextToken` 原地切分（空格分隔，token 末尾写 `'\0'`），零分配 —— [token.hpp](../temp/Dust_Zephyr_Tree/framework/shell/token.hpp)。
- 命令表：`ShellCmdEntry { name, handler, help }` + `REGISTER_SHELL_CMD(name, help, handler, ident)` 放进链接段 —— [shell_cmd.hpp](../temp/Dust_Zephyr_Tree/framework/shell/shell_cmd.hpp)。
- 分派：`ProcessLine` 取第一个 token，线性遍历段比对，命中把**剩余原始串**交给 handler —— [shell.cpp:60-77](../temp/Dust_Zephyr_Tree/framework/shell/shell.cpp#L60-L77)。
- 帮助：`PrintHelp` 遍历同一段，`snprintf("%-8s %s", name, help)` 每族一行；`h` 本身也是注册项 —— [shell.cpp:42-50, 83-89](../temp/Dust_Zephyr_Tree/framework/shell/shell.cpp#L42-L50)。

**不取：**

- `log` 子系统（`log_queue` / `log_transport` / 通道策略）一行不动——当前工程这份已经是 Linux 版。
- `boot` / `thread` 命令族不搬：本项目没有 `.boot_timing` 段和 `thread_registry`，搬过来只有空表。
- 参考的链接脚本 `SECTION_PROLOGUE(...) GROUP_LINK_IN(ROMABLE_REGION)` 是 Zephyr 链接器语法，Linux 不适用；本工程复用现有 `dust_init.ld`（`INSERT AFTER .data`）或直接用 GNU ld 自动边界（见 §3 决策 D）。
- 不新增 Kconfig 符号：两个新头文件属于已有 `DUST_CMD_SHELL` 能力，由现有 `DUST_CMD_SHELL_LOG` / `DUST_CMD_SHELL_VAR` 的 `select` 链覆盖。

**边界：** 只动 `framework/cmd/shell/{shell.hpp,shell.cpp,token.hpp,shell_cmd.hpp,var.cpp,log.cpp}`。`framework/cmd/shell/var.hpp` 的注册宏与 `VarEntry` 不改，`log_*.hpp`、`Init_entry.*`、`project/` 一行不动。B 部分（§11）只动 `shell.hpp` / `shell.cpp`，**不改 `log_transport.*`**——回显重绘已经由 `Log::UpdateInput` → `DrawInput` 完成，历史只需要改 `line_` 和 `cursor_`。

## 3. 病灶与差距（每条带算法）

| # | 病灶 | 怎么算出来的 | 现状 | 目标 |
| --- | --- | --- | --- | --- |
| 1 | **新增一族要改两处，其中一处离实现很远** | 数 `shell.cpp` 中新增一族要加的行：分派分支 4 行（`else if (strcmp…` + `{` + 调用 + `}`）+ `CmdHelp` 1 行；族内用法串 1 行 → **2 文件 5 行** | 2 文件 5 行 | 1 文件 2 行（宏 1 + 用法串 1），触点比 **2.5 : 1（行）**、**2 : 1（文件）** |
| 2 | **命令名有两个真源** | 每个族名在 `ProcessLine`（匹配）与 `CmdHelp`（显示）各写一遍；漏改一边 → 编译不报错、帮助与行为不一致 | 3 族 × 2 处 = 6 处 | 每族 1 处 |
| 3 | **每次命令都做堆分配** | 输入 `var set camera_exposure_us 8000` 共 29 字节：`istringstream` 内部 stringbuf 持有一份整行拷贝（>libstdc++ SSO 阈值 15 → 1 次分配）；`name` = 18 字节（>15 → 第 2 次）。短名（`display.show` 12B）走 SSO 不分配，**只有长变量名才触发第 2 次** | 长名命令 ≥ **2** 次/行 | `NextToken` 原地切分 **0** 次/行 |
| 4 | **参数校验各写一套，语义不一致** | `log.cpp` / `var.cpp` 都用 `is >> extra` 拒绝多余 token（共 6 处），但报错文案与判定方式不同：`var` 回 `?: var list|get…`，`log` 回 `?: log list|on…` | 2 套解析器 | 1 套切分 + 各族自己的判定 |
| 5 | **命令表的"存在性"没有单一来源** | 现在"有哪些族"由 `shell.cpp` 的 if-else 链定义；链上没有的 handler 即使实现完整也永远收不到命令 | 1 张隐式表 | 1 个链接段 |
| 6 | **帮助内容与注册不在同一行** | `CmdHelp` 里 5 行文字与 `var.cpp` / `log.cpp` 的实现文件分离，新增族时容易只做一半 | 帮助 5 行、实现 2 文件 | 帮助字段与 handler 同一行注册 |

**不构成取舍依据的量：** 每个注册项占 3 个指针 = **24 B**（x86-64），3 族 = 72 B `.rodata`；删掉的 if-else 链（4 个字符串字面量 + 3 个调用点）量级相当，差 10 B 上下。段遍历是 n 项 × `strcmp`，与 if-else 链同为 O(n)，3 个族时差异不可测。**换架构的收益在 §3 第 1、2、5、6 条，不在运行期速度。**

## 5. 目标链路

```text
stdin 字节流
   │  ProcessChar（行编辑，不动）
   ▼
line_（std::string，可写 data()）
   │  ProcessLine
   ├── NextToken(line, cmd)            ← token.hpp：跳过空格、切出第一个 token、原地写 '\0'
   ├── cmd 为空 → return
   ├── for (e = ShellCmdBegin(); e < ShellCmdEnd(); ++e)
   │      └── strcmp(e->name, cmd) == 0 → e->handler(rest)   ← rest 是命令名之后的原始串
   └── 未命中 → "unknown command"
                                              ▲
                     .shell_cmd 段（KEEP，启动后只读）┘
           REGISTER_SHELL_CMD("var", "var list|get|set", Var::Process, var)   ← 写在各族自己的 .cpp 末尾
           REGISTER_SHELL_CMD("log", "log list|on|off|mode", Log::ProcessLogCommand, log)
           REGISTER_SHELL_CMD("h",   "help", Shell::PrintHelpWrapper, h)      ← 与参考一致，h 也是表项
```

Handler 签名直接沿用参考的 `void (*)(uint8_t* args)`：`Var::Process` 与 `Log::ProcessLogCommand` 当前就是 `void(uint8_t*)`，注册处不需要适配层。

### 11.3 算法

```text
PushHistory(s):
    if s 为空 → return                       // 空行不执行，也就不进历史
    if history_count_ > 0 且 s == 最近一条 → return   // 见决策 F
    if history_count_ < kHistorySize:
        history_[history_count_++] = s
    else:
        整体左移一格（15 次 string 赋值），history_[kHistorySize-1] = s
    history_pos_ = history_count_

HistoryPrev():
    if history_count_ == 0 → return
    if history_pos_ == history_count_:        // 首次按 ↑：先存草稿
        history_draft_ = line_
    if history_pos_ == 0 → return             // 已在最旧一条，停住
    --history_pos_
    line_   = history_[history_pos_]
    cursor_ = line_.size()

HistoryNext():
    if history_count_ == 0 → return
    if history_pos_ == history_count_ → return
    ++history_pos_
    line_   = (history_pos_ == history_count_) ? history_draft_ : history_[history_pos_]
    cursor_ = line_.size()
```

**为什么用"位置 = count 表示草稿"：** 上键进入历史前先把当前没提交的半行存进 `history_draft_`，下键回到最新一条之后恢复它——否则按几下 `↑` 再按 `↓`，正在敲的那半行就没了。

**为什么整行替换而不是保留光标位置：** 历史项与当前行的内容通常完全不同（连长度都不一样），把光标映射过去没有意义；统一落到行尾，与 `Home`/`End` 现有实现一致。

**代价：**

| 项 | 值 |
| --- | --- |
| 每项结构开销 | `sizeof(std::string)` = **32 B**（本机 x86-64 实测） |
| 16 项固定开销 | 16 × 32 = **512 B**（`Shell` 实例在静态存储区，`shell_` 本来就是 static） |
| 内容堆分配 | 每条 > 15 字节的命令 1 次（SSO 阈值）；≤ 15 字节不分配 |
| 插入 | 未满时 O(1)；满了左移 15 次赋值（命令频率下可忽略） |
| 方向键响应 | 1 次字符串拷贝 + 1 次 `DrawInput()` 写屏 |

### 11.4 边界行为

| 情形 | 行为 |
| --- | --- |
| 空行回车 | 不执行、不进历史（现有逻辑就跳过） |
| 超长被丢弃的行 | 不进历史（`discard_line_` 为 true 时不 push） |
| 连续重复命令 | 按决策 F 处理 |
| 历史为空时按 `↑`/`↓` | 无动作，不报错 |
| 在最旧一条继续按 `↑` | 停在最旧一条（不回绕） |
| 在最旧一条按 `↓` | 逐条回到草稿 |
| 回显 | 由现有 `Log::UpdateInput` 重画，日志插播时 `DrawInput` 会自动重绘当前行，无需改 |
| 非终端输入（重定向） | `ProcessChar` 照常执行，历史照常记录，只是没有回显 |
| 应用光标模式终端（发 `\x1bOA`） | 与 `\x1b[A` 同样处理（`Home`/`End` 已是这个写法） |

### 11.5 待你拍板的决策点

| # | 分叉 | 选项 | 建议 |
| --- | --- | --- | --- |
| F | 连续重复命令 | ① 相邻重复不重复记录（`a a b` → 历史 `a b`）；② 原样记录 | ①，否则连按两次同一条命令后要按两次 `↑` 才回到上一条 |

### 11.6 验收

**静态：**

```bash
rg -n '\\x1b\[A|\\x1b\[B|\\x1bOA|\\x1bOB' framework/cmd/shell/shell.cpp   # 4 个转义串
rg -n 'kHistorySize|history_pos_|history_draft_' framework/cmd/shell/shell.hpp  # 4 个成员
rg -c 'UpdateInput' framework/cmd/shell/shell.cpp   # 仍为 1（不新增重绘调用）
```

**运行期（你发话后）：**

1. 输入 `var list` 回车 → `↑` 应显示 `var list`，光标在行尾；
2. 再按 `↑` → 显示上一条；`↓` → 逐条回来，最后回到空行；
3. 输入半行 `var ge` 不回车，按 `↑` 再按 `↓` → 恢复 `var ge`，光标在行尾；
4. 按 `↑` 到某条后直接回车 → 该命令正常执行；
5. 连按 17 条不同命令后按 17 次 `↑` → 停在第 16 条（最旧），不崩、不回绕；
6. 日志在按 `↑` 期间插入输出 → 当前显示行被重绘回来（现有 `DrawInput` 行为）。

### 11.7 失败回退表

| 症状 | 先查 | 再查 | 最后才查 |
| --- | --- | --- | --- |
| `↑` 仍无反应 | 转义分支的判定顺序（`escape_.size() == 2` 提前 return 那条） | 终端实际发的是 `\x1b[A` 还是 `\x1bOA` | 是否被 `escape_.size() < 16 && (ch < '@' \|\| ch > '~')` 提前拦掉 |
| 历史记了但 `↑` 出来是旧行 | 回车分支 push 是否在 `ProcessLine` **之前**（`ProcessLine` 会原地改写 `line_` 的缓冲区） | `history_pos_` 是否在 push 后复位为 `history_count_` | 决策 F 的去重是否把新命令吞了 |
| 按 `↓` 回不到半行草稿 | 首次 `↑` 时 `history_draft_` 是否保存 | `history_pos_ == history_count_` 的分支 | 是否在回车后被误清 |
| 显示行变乱 / 光标错位 | `cursor_` 是否设为 `line_.size()` | `DrawInput` 的 255 上限与 `room` 计算 | 终端宽度 `ioctl` 失败时退化为 80 列 |
| 历史串含 `\0` | 不适用：输入字符过滤在 `' '`~`'~'`，不含控制字符 | — | — |
