# ROS 2 与 EtherCAT 双向话题桥接

## 数据方向

```text
MCU → EtherCAT Inputs → ecat_rx 内部话题 → ROS 2 发布 /ecat/rx_pdo → 外部进程
MCU ← EtherCAT Outputs ← ecat_tx 内部话题 ← ROS 2 订阅 /ecat/tx_pdo ← 外部进程
```

两个 ROS 2 话题均使用 `std_msgs/msg/UInt8MultiArray`，`data` 长度为 256，`layout` 留空。QoS 为 BestEffort、KeepLast(1)、Volatile。接收方需选择兼容 QoS。

## 上行

EtherCAT 成功读取后，完整 PDO 原样发布；业务 CRC 校验失败也转发。SOEM 读取失败不发布旧数据。前 20 字节为 MCU 状态包。

## 下行

外部进程发送完整 256 字节 PDO，前 15 字节为 MCU 速度命令，其余由发送进程填充。帧头、小端 float32、CRC 由外部进程组装，桥接层不改字节；MCU 检查业务协议。

首次收到 ROS 命令之前保留 `ecat.linear_x/y` 的 var 调速。收到 ROS 消息后接管；有效长度命令最近接收时间不足 100 ms 时按原样下发，速度不变也需要周期发布。100 ms 没有新命令、或收到长度不等于 256 的消息时，主站组装合法零速度包，不回退到 var。重新收到完整命令后恢复下发。

此处时间戳是主站接收时间，不是导航算法生成时间。发送端不能无限刷新旧目标来掩盖导航停更。MCU 收到业务错误帧时按其固件规则使命令无效。

## 线程与生命周期

EtherCAT 线程独占 SOEM。ROS 2 线程拥有独立 Context、Node、Publisher、Subscription 和 SingleThreadedExecutor。任务执行有界 `spin_some`，再等待上行话题最多 1 ms，保证 MCU 停止上报时仍处理下行回调。

现有框架管理信号、启动和退出。停止时 RequestStop 并关闭上行 Channel 唤醒等待，Join 后移除节点并释放 ROS 2 资源。ROS 2 故障隔离，不停止 EtherCAT；下行命令通过本地年龄判断归零。内部话题为单槽最新值，允许跳帧，不保证逐帧交付。

## 文件与开关

- `framework/topic/ecat_rx/ecat_rx.hpp`：双向消息和 Channel 声明。
- `project/thread/ethercat/trd_ethercat.cpp`：定义 Channel、发布上行、消费下行。
- `project/thread/ros2/trd_ros2.cpp`：双向 ROS 2 桥接及生命周期。
- `TRD_ROS2`：默认开启；关闭后不依赖 ROS 2。

## 运行与验证

本机使用 ROS 2 Humble，`dust run` 已自动加载环境；构建前执行：

```bash
source /opt/ros/humble/setup.bash
dust build
dust run
```

外部进程加载 ROS 2 环境后订阅上行：

```bash
ros2 topic echo /ecat/rx_pdo --qos-reliability best_effort
```

双方使用一致的 ROS_DOMAIN_ID。当前运行脚本通过 sudo 提权，如使用非默认域，需要确保提权后的配置一致。

已完成编译、仓库外独立进程双向 256 字节一致性验证，以及发送映像接管、100 ms 停更归零和无效长度标记归零验证。未进行实机底盘命令验证。未新增仓库测试文件。
