## 2. 改了什么东西

### 2.1 PDO 布局（pdo_layout.hpp）

- 期间试过"紧凑版"：Header 30 B / Remote 28 B / IMU 50 B、电机反馈 4×12 B、命令头 36 B、电机区 8 B，`slot_map_version=2`。
- **最终回退到从站 v1 布局**（与从站 `6424ed7` 对齐）：
  - TxPDO：FeedbackHeader 40 B @0，RemoteFeedback 32 B @40，ImuFeedback 56 B @72，`motor_feedback[128]` @128；
  - RxPDO：CommandHeader 48 B @0，`motor_command[128]` @48，`device_operation[32]` @176，`diagnostic[16]` @208，`reserved[32]` @224；
  - `kSlotMapVersion = 1`，双向各 256 B，assert 全保留。

### 2.2 EtherCAT 主站驱动（ecat.hpp，调试期的改动，回退后不在当前分支）

- 网口：曾固定 `enp2s0`（自动探测选中了没接从站的 `enp3s0`），**当前已恢复自动探测**（`interface_name` 留空 → `FindCarrierInterface()`）。
- 重试间隔：`thread_init` 的 1000 ms → 100 ms。
- 邮箱 SM 自愈：主站进 INIT 会清 SM，从站 PDI 又不能配，改为每轮 PREOP 前补写
  `SM0=0x1000/128/control 0x26/activate 1`、`SM1=0x1080/128/control 0x22/activate 1`，并回读确认。
- 补齐 SOEM 的邮箱字段：`mbx_wo=0x1000`、`mbx_ro=0x1080`、`mbx_l=mbx_rl=128`、`mbx_proto |= ECT_MBXPROT_COE`（SII 偶发读成 0）。
- 顺序：PREOP（轮询 ALSTAT 直到真正进入）→ `ecx_readPDOmap`（CoE 在线解析）→ `ecx_config_map_group` → 重写 `SM2=0x1100/256/control 0x64`、`SM3=0x1400/256/control 0x20` → 请求 OP。
- `RequestOperational()`：请求 OP 前先显式 `RequestState(SAFE_OP)`。
- `RequestState()`：AL 控制写带 ACK 位；等待状态改为直接 `FPRD(ALSTAT)`（不信 `ecx_statecheck`）；`write_wkc=0` 视为失败重写；超时打印 `raw_alstat` / `raw_code`。
- `readPDOmap` 失败立即放弃本轮（省掉 1 s 的 OP 空等）。
- 站地址诊断：SAFE-OP 等待期间寻址读失败时用广播读 `ALSTAT` 与 `0x0010` 对照；曾加过自动恢复（广播切 INIT 再写站地址），**已删除**。

### 2.3 线程与话题（trd_ethercat.cpp）

- 回退版本保留：命令头填充（`slot_map_version=1`、`byte_length=256`、boot id / feedback seq 回显、会话、租约、compute_time）、反馈解析、`Recover` 重连。
- 已移除：`ecat_chassis` 话题的 include、底盘命令订阅者、`UpdateChassisCommand()`、`PublishFeedback()`；`motor_command[128]` 当前整区清零（前 8 B 预留给 C620 0x200 帧，从站 v1 不消费）。
- `project/Kconfig` 中 `TRD_CHASSIS default n`。

## 3. 确定的问题（按定位顺序）

1. **网口选错**：自动探测选了 `enp3s0`（接的是普通网络），`ecx_config_init` 报 0 slaves。从站实际接在 `enp2s0`（100 M 链路）。
2. **SII 偶发读成 0**：`mbx_l/mbx_rl/mbx_proto` 时有时无，导致主站不尝试 CoE、退回 SII 的 1 B 映射，SAFE-OP 因 SM3 长度不符报 `0x001e`。已在主站按协议补齐邮箱字段。
3. **`mbx_ro=0`（关键）**：SOEM 的 SDO 应答从 `slavelist[].mbx_ro` 指定的地址读取，该值为 0 时 SDO 永远读不到应答 → `ecx_readPDOmap ret=0`。补齐 `mbx_wo/mbx_ro` 后 SDO 立即正常：`SDO read 0x1C00:0 ret=1`、`readPDOmap ret=1 (256 B + 256 B)`、`mapped 513 bytes`、通过 CoE 得到 256+256 映射。
4. **PREOP 没等就发 SDO**：只写一次 AL 控制就立刻读状态，从站还停在 INIT，SDO 被拒。改为轮询 ALSTAT 直到真正进入 PREOP。
5. **config_map 后直接请求 OP**：`ecx_config_map_group` 只写 SAFEOP 不等确认，紧接着写 OP 会被从站按非法跳转拒绝（`0x0011`）。改为先显式等到 SAFE-OP。
6. **WKC 不可信**：多个轮次 `write_wkc=0`，但 ALCTL 读回值证明写已生效（另有 `wkc=1` 时值却没落的情况）。状态判定统一改为读回值 + 直读 ALSTAT。
7. **站地址被清成 0（未定论）**：SAFE-OP 等待期间出现"过程数据 `wkc=3` 正常、寻址读全部 wkc=0、广播读 `0x0010` 返回 0x0000"；当时曾尝试在 INIT 下重写站地址（读回 0x1001 成功但下一拍又变 0）。从站侧源码排查确认 PDI 从不写 `0x0010`（zephyr_user/midlayer 与 SSC 均无该写入），故该现象的根本原因尚未闭环，主站侧的自动恢复代码已删除，保留只读诊断。

## 4. 为什么回退到 4af5d1e

- **该版本实测能收发**：主站进 OP（`all 1 slaves in OP in 0 ms`）、`session 1 accepted`、`motor command active`；从站日志出现 `al_state -> 0x08 (first outputs)` 与 `rx resumed`。
- 后续在主站驱动上做的实验性改动（SM 自愈、SDO 顺序、SAFE-OP 等待、站地址诊断等）引入了新的不稳定（`0x001e`、`0x0011`、`readPDOmap ret=0`、站地址 0），在问题未闭环前不再叠加。
- 从站当前固件（`6424ed7`）的 PDO 是 v1 布局（256 B 双向、`slot_map_version=1`），回退后的主站布局与之逐字节一致。

## 5. 后续

- 调试期的全部主站改动仍保留在：本地 `backup-91d8696` 分支、远程 `main`（`97d0cad…91d8696`），可随时取回对照。
- 底盘闭环（`TRD_CHASSIS`）当前关闭；若重新接入，需要在 v1 布局上重新定义电机区（从站 `6424ed7` 不消费 `motor_command`）。
- 站地址清零的问题若复现，优先排查主站侧 SOEM 的地址探测/恢复路径与从站 AC 状态切换时序，从站侧已排除 PDI 写 `0x0010`。
