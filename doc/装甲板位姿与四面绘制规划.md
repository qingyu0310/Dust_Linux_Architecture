**由参考与本机数字算出来的量（验收线用它们定，不用"看着差不多"）：**

- **单目测距误差**。投影宽度 `w = f·W/d`，而相对深度误差等于相对宽度误差 `σ_d/d = σ_w/w`，所以

  ```text
  σ_d = d² · σ_w / (f · W)
  ```

  取 `f = 1800 px`、小装甲板 `W = 0.135 m`、角点误差 `σ_w = 1 px`：

  | 距离 d | 投影宽 w | σ_d |
  | --- | --- | --- |
  | 1 m | 243 px | **4.1 mm** |
  | 2 m | 162 px | **16.5 mm** |
  | 3 m | 81 px | **37.0 mm** |
  | 5 m | 49 px | **102.9 mm** |

  误差随 `d²` 增长，与距离无关的绝对值不存在——**验收必须分档给数**。

- **半径的单帧不可观测性（本规划最关键的一个数）**。两帧估半径 `r = |p₂−p₁| / |û₁−û₂|`，而小转角下 `|û₁−û₂| = 2·sin(Δyaw/2)`，于是

  ```text
  σ_r = √2 · σ_p / (2 · sin(Δyaw/2))
  ```

  转速 2 rad/s、30 fps 时 `Δyaw = 3.82°/帧`，代入 `σ_p = 37.0 mm`（3 m 处的 σ_d）：

  ```text
  2·sin(1.91°) = 0.0663
  σ_r = 1.414 × 0.0370 / 0.0663 = 0.789 m
  ```

  **0.789 m 是名义半径 0.2 m 的 3.9 倍**——单帧或相邻两帧的半径估计毫无意义。要 `σ_r ≤ 50 mm` 需 `2·sin(Δyaw/2) ≥ 1.047`，即 **Δyaw ≥ 63.1°**；按 2 rad/s 折算 **0.55 s ≈ 17 帧**。这是"四面必须跨帧"的定量结论，也是把 PnP 与跟踪分成两阶段的原因。

- **半径的物理上界**。参考把 `r` 与 `r+l` 都钳在 `[0.05, 0.50] m`。上界 0.50 m 对应一辆半径半米的旋转体——比这个还大的"半径"必定是估计发散，不是真的车。

- **收敛前的外推误差**。若在第 17 帧前就按未收敛的 `r` 画另外三面：`Δyaw = 3.82°`（单帧）时 `σ_r = 789 mm`，圆心位置误差 0.79 m 在 3 m 处投影 `0.789 × 1800 / 3 = 473 px`——**整幅画面宽度才 1440 px，外推的三面会画到画面外**。所以"未收敛不画四面"不是保守，是不画错东西。

- **平面靶 PnP 的双解歧义**。IPPE 对 4 个共面点有两个解（法向相反），参考用 `optimize_yaw()` 配合云台 yaw 消歧。本工程没有云台，所以**"重投影误差小"不能证明位姿对**——两个解的重投影几乎一样。这是本规划必须单列方法学约束（§4）的原因。

- **噪声地板**。标定残差 0.106212 px，检测角点本身约 1 px 量级，所以重投影误差的合理下限在 **1 px 上下**；拿它当"算法不准"的判据是错的，真正的判据是它与**绝对距离核对**是否一致。

## 4. 方法学约束

1. **物点顺序与坐标系约定是一切的地基**，必须先用合成自检锁死：给定位姿投影出四点，再喂给 `solvePnP` 反解，解不回来就是顺序/单位/符号错了，与相机无关。**这一条不通过，后面所有数字都不可信。**
2. **重投影误差不能单独作为位姿正确的判据**：平面靶双解的重投影几乎一致（§2）。必须补**绝对量核对**——拿尺子量出真实距离，与 `‖tvec‖` 比。
3. **未收敛不画另外三面**：按未收敛的 `r` 外推会把点投到画面外（§2 算的 473 px 误差），画出来只会误导。
4. **不照抄参考的数值**：物点尺寸（135/230/56 mm）是实物量、可以取；但过程噪声、`P0`、转速这些是**另一台相机 + 另一个帧率**下标出来的，必须用本机数据定。
5. **参考的 EKF 与本工程的 EKF 接口不同**，移植时要改调用方式（见 §5.4），不是复制粘贴。
6. **不把位姿塞进 `vision_to`**：先保持 `vision_to` 契约不变，PnP/跟踪结果只在视觉线程内用（画在图上）。是否外发等有明确的第二个消费者时再谈。

## 5. 算法与公式

### 5.1 物点与坐标系（照 `solver.cpp:14-27`，先冻结）

板系：`x` 为板法向，`y` 沿装甲板宽度，`z` 沿灯条方向，原点在板心，板面即 `x = 0`。四角点按 LT/RT/RB/LB 顺序给：

```text
LT = {0, +W/2, +L/2}
RT = {0, -W/2, +L/2}
RB = {0, -W/2, -L/2}
LB = {0, +W/2, -L/2}
```

`W` 取 `SMALL_ARMOR_WIDTH` 或 `BIG_ARMOR_WIDTH`（由 `ArmorSize` 决定），`L = LIGHTBAR_LENGTH`，单位一律**米**。

> **映射假设（必须验证，不能默认）**：我按"图像 LT 在左上、RT 在右上"推出上面的符号分配（+y 对应图像左侧、+z 对应图像上方）。但我**没有读参考的检测器**去确认它 `armor.points` 的实际顺序，所以这是一条待验证的假设——`参考 target.hpp:91` 只写了 `std::vector<cv::Point2f> points;`，没写顺序。同一顺序若把 y/z 之一写反，重投影会大一个量级；写反 x 符号（法向朝里还是朝外）只改变解的 yaw 分支、重投影几乎不变（就是 §2 的双解歧义）。**验证方式见阶段 1 的合成自检**。

> **朝向与主点**：跟踪器发布的帧已经过 `cv::flip(-1)`（`trd_camera.cpp`），内参也是在同样翻转后的像素上标定的，两边同源，**不需要再翻**。若哪天去掉相机线程的翻转，主点要换成 `(W−1−cx, H−1−cy)` 并重标——两者必须同源，这是硬约束。

### 5.2 单帧 PnP

```cpp
cv::Mat camera_matrix = (cv::Mat_<double>(3, 3) << fx, 0, cx, 0, fy, cy, 0, 0, 1);
cv::Mat distort_coeffs = (cv::Mat_<double>(1, 5) << k1, k2, p1, p2, k3);
cv::Vec3d rvec, tvec;
cv::solvePnP(object_points, corners, camera_matrix, distort_coeffs, rvec, tvec,
             false, cv::SOLVEPNP_IPPE);
```

- 选 `SOLVEPNP_IPPE`：4 点共面的专用解，与参考一致。
- `useExtrinsicGuess = false`：每帧独立解，不继承上一帧。
- 输入校验：四点必须全部有限、`ArmorSize != Unknown`、外接框非退化；任一不满足**不解算**，显式标记为无效，不返回看似有效的默认位姿。
- 参数只有 6 个（R 3 + t 3），观测方程 8 个（四点各 2），过定比 **1.33:1**——**几乎没有冗余**，所以精度完全取决于物点对不对、角点准不准。

### 5.3 重投影校验

```cpp
std::vector<cv::Point2f> projected;
cv::projectPoints(object_points, rvec, tvec, camera_matrix, distort_coeffs, projected);
double error = Σ‖corners[i] − projected[i]‖ / 4;   // px
```

判据分两层：**贴合**（≤2 px，看角点与几何是否自洽）与**绝对距离**（分档比对，看尺度对不对）。只有"贴合"通过而"距离"不过，说明物点尺寸或单位错了；只有"距离"对而"贴合"不过，说明畸变没生效或角点本身有偏差。

### 5.4 跨帧车模型（移植要点）

状态向量与参考 `target.cpp:31-40` 一致，**11 维、全在相机系**（去掉所有云台/世界量）：

```text
x = [cx, vx, cy, vy, cz, vz, a, w, r, l, h]
      ↑位置(3)   ↑速度(3)   ↑转角 ↑角速度 ↑半径 ↑半径差 ↑高度差
```

- **过程模型**：位置匀加速 + 转角匀速，即参考 `target.cpp:81-99` 那个 `F`。
- **四面推导**（照 `target.cpp:466-491`）：

  ```text
  angle_i  = limit_rad(a + i·2π/4)
  r_i      = (i ∈ {1,3}) ? r + l : r
  armor_xyz_i = { cx − r_i·cos(angle_i), cy − r_i·sin(angle_i), cz + (i∈{1,3} ? h : 0) }
  armor_yaw_i = angle_i
  ```

  注意是 `−r·cos`（参考也是减号，不是加号）。
- **物理约束**（照 `target.cpp:423-433`）：`r` 与 `r+l` 都钳在 `[0.05, 0.50] m`。
- **观测**：把该 id 的位姿反投回像素四点，与实测四点求残差。**雅可比用有限差分数值求**（照参考 `target.cpp:389-403` 的做法），省去手推解析式。
- **收敛判据**（照 `target.cpp:438-445`）：`update_count > 3` 且未发散（半径在物理范围内）。
- **接口差异（必须改，不能照抄）**：参考的 `tools::ExtendedKalmanFilter` 在 `update` 里接受 `h(x)` 与 `z_subtract`、在 `predict` 里接受 `F/Q/f`，且自带角度归一化；本工程的 `algorithm::filter::ExtendedKalmanFilter` 是**模板 + 分离的 `predict(f, F)` / `correct(z, h, H)`**（`ekf.hpp:57,97`），**没有角度归一化、没有自定义减法**。移植时要么在调用侧自己把角度包回 `(−π, π]`，要么给模板加。这是本次移植最容易出错的地方，写在注释里。

### 5.5 关联

预测四面各自重投影四点，与当帧候选按残差平方和做**全局最近邻**（贪心，每次取全场最小代价配对，照 `tracker.cpp:495-524`）：

```text
cost(obs, id) = Σ_k ‖projected_k(id) − corners_k(obs)‖²
```

超过门限的配对直接丢弃，不参与本轮更新。转速 2 rad/s、半径 0.2 m 时切向速度 `0.2 × 2 = 0.4 m/s`，帧间移动 13 mm，在 3 m 处投影 `13 × 1800/3000 = 8 px`——门限按这个量级留一倍余量即可。

## 7. 分步骤

### 阶段 0：冻结约定（只读 + 一次核对）

**做什么：** 把 §5.1 的物点、`W/L` 值、LT-RT-RB-LB 配对写进代码注释与常量；在 `trd_vision.yaml` 落 §6 的键。

**验收数字：** 拿实物装甲板量 `W` 与 `L`，与配置值的偏差 ≤ 2 mm。

**失败分叉：** 实物与参考值不符 → 用实测值，不要为对齐参考改动配置。

### 阶段 1：算法层单帧 PnP（先做，不改线程）

**做什么 / 落点：** `framework/algorithm/vision/pose/armor_pose.hpp/.cpp`；Kconfig 加 `DUST_VISION_POSE`；根与 framework 的 CMake 条件按 §6 改；合成自检放 test 线程 `trd_test.cpp` 的 `CheckPose()`，由 `TRD_TEST` 拉起。

**验收数字（三条都要过）：**

1. **合成自检**：给定位姿 → `projectPoints` 造四点 → `SolvePose` 反解，`tvec` 三分量误差 < **1e-3 m**、重投影 < **1e-6 px**。这一条同时验证物点顺序与单位——顺序错则误差到 1e-1 量级、单位错则 tvec 差 1000×。
2. **绝对距离核对**：把板放在量好的 1.0 / 2.0 / 3.0 m，`‖tvec‖` 的相对误差 ≤ **3%**（3 m 处即 90 mm，是 §2 噪声地板 37 mm 的 2.4 倍）。**这一条防的是双解歧义**——重投影过不了这一关。
3. **实拍贴合**：实机对静止板解一次，重投影误差 ≤ **2 px**，并把四点画出来目视贴合。

**失败分叉：** 自检 1e-1 → 查物点顺序与单位，不要先调别的；距离差 1000× → 查点距是 mm 还是 m；重投影好而距离错 → 查 `W` 用的是小还是大装甲板（`ArmorSize` 映射）；只有画面边缘差 → 查畸变是否传进 `solvePnP`。

### 阶段 2：接入视觉线程，画"当前检测到的每一块"

**做什么 / 落点：** `trd_vision.cpp` 的 `LoadVisionConfig()` 读 §6 的键；`Task` 里每帧对每块 `DetectedArmor` 调 PnP，把位姿轮廓（`ProjectPose` 的四点或板框）画在发布帧上——**此时画的是真的测到的那块，不是外推的另外三面**。

**验收数字：** 静止板前，发布帧上四点轮廓贴合；每秒统计里输出 `pnp ok / invalid` 计数与平均重投影误差（照现有 `LogReport` 的窗口风格，不逐帧打）。

**失败分叉：** `invalid` 比例高 → 查是 `ArmorSize::Unknown` 还是四点退化，不要放宽校验掩盖；重投影均值 > 2 px → 回阶段 1 的第 3 条。

### 阶段 3：算法层跨帧追踪 + 四面推导

**做什么 / 落点：** `framework/algorithm/vision/track/armor_tracker.hpp/.cpp`；Kconfig 加 `DUST_VISION_TRACK`。

**验收数字：** 用阶段 1 的合成手段造一串带已知 `r`/`ω` 的观测序列，喂进跟踪器：**半径收敛到真值 ±10%**，且**在同一转速下所需帧数 ≤ 17**（§2 算的界）。**这一条是纯离线的，不需要相机**，是验证跟踪器本身正确性的唯一手段。

**失败分叉：** 收敛慢于 17 帧 → 先查过程噪声是否给得过大（协方差一直在重开）；半径收敛到 0.05 或 0.50（钳制边界）→ 说明观测没能约束半径，查关联是否把 id 配错；角度出现 ±π 跳变 → 本工程 EKF 没有角度归一化（§5.4 的接口差异），在调用侧补。

### 阶段 4：接入运行链，画四面

**做什么：** `trd_vision.cpp` 里每帧 PnP → 喂跟踪器 → 取 `armor_xyza_list()` → 四面各自重投影 → 描在发布帧上；未收敛时只画测到的那块并在日志标 `state`。

**验收数字：** 实机对着自转的车：收敛后（`update_count > 3`）四面轮廓稳定贴合，`state=tracking`；收敛前日志是 `detecting` 且只画一块。整车参数（`r`、`armor_num`）来自 §6 的配置，不是硬编码。

**失败分叉：** 四面与画面里的板对不上 → 先查 `angle_i` 的符号与 `r_i` 的取法（`i∈{1,3}` 用 `r+l`），再查 `armor_num` 是否与车一致；一直收敛不了 → 回阶段 3 的离线验收，不要在现场调噪声。

## 8. 顺序为什么不能换

1. **物点约定（阶段 0）必须最先冻结**：它是唯一的地基，顺序或单位一变，后面所有误差数字全部作废、且无法比较。
2. **单帧 PnP 必须独立验完再做跨帧**：跟踪器的观测模型就是"把状态投成像素四点"，PnP 与重投影不对时，误差会被 EKF 吸收成"观测噪声"或"状态偏差"——那时你无法区分是 PnP 错还是滤波器错。
3. **`calib3d` 的查找条件必须在阶段 1 就改**：不改则 `solvePnP` 链接失败，阶段 1 根本编不过；不能留到最后。
4. **跨帧必须早于画四面**：§2 算出未收敛时外推误差 473 px（画面宽的 1/3），没有跟踪就画四面必然画错。
5. **跟踪器要先离线验（阶段 3）再上实机（阶段 4）**：离线用合成序列能确定"收敛慢"是滤波器问题还是数据问题；先上实机的话，两种原因混在一起。
6. **`vision_to` 契约不动**：整条链只用现有通道，避免"改契约 + 加算法"两件事同时做、互相掩盖。

## 9. 失败回退表

| 症状 | 先查 | 再查 | 最后才查 |
| --- | --- | --- | --- |
| `solvePnP` 链接失败 | `find_package(... calib3d)` 的条件是否已扩到 `DUST_VISION_POSE` | `framework_vision` 是否链了 `opencv_calib3d` | 该库的建库条件是否也放宽了 |
| 重投影误差 ~1e-1 量级 | 物点顺序（LT/RT/RB/LB 对应） | 单位是 m 还是 mm | 角点是否已按 `flip(-1)` 后的坐标 |
| 距离差 1000× | `tvec` 的单位与点距一致吗 | 内参来自标定还是硬编码 | 是否重复做了一次 mm↔m |
| 重投影合格但距离不对 | `ArmorSize` 是否映射错（大/小板取反） | 板上量到的 `W` 与配置值是否一致 | 相机是否被重新对焦（内参失效） |
| 画面边缘重投影差 | 畸变是否传进 `solvePnP`/`projectPoints` | 边缘角点是否被裁切 | 是否需要重标 |
| 半径收敛到 0.05 / 0.50 | 关联是否把 id 配错 | 观测是否只用了同一面（车没转） | 初值 `armor_radius_init_m` 是否离谱 |
| 收敛慢于 17 帧 | 过程噪声是否过大 | 帧率是否远低于 30 fps | 该车转速是否确实低 |
| 角度出现 ±π 跳变 | 本工程 EKF 无角度归一化（§5.4） | 关联代价是否跨过 ±π | 状态里角度是否该用别的表示 |
| 四面画到画面外 | 是否在收敛前就画了四面 | `r` 的钳制是否生效 | `angle_i` 符号是否写反 |

## 10. 明确不做

1. **不引入云台系/世界系**：`R_camera2gimbal`、`t_camera2gimbal`、`R_gimbal2imubody`、`ypr_in_world`、`ypd_in_world` 一律不引入——本工程没有云台与 IMU 设备层，没有来源。
2. **不做 `optimize_yaw()`**：平面靶双解改用"绝对距离核对 + 跨帧"来消歧，不搬 140° 暴力搜索。
3. **不做 `ypda_measurement_covariance()`**：那是给下游滤波器调权的，本阶段没有下游。
4. **不做多目标**：只跟踪一辆车（一份状态）；多目标、锁定、切换留给后续规划。
5. **不改 `vision_to` 契约**：位姿与跟踪结果暂不外发，只在视觉线程内用于绘制。
6. **不做动态 ROI、不做 MPC、不接云台与开火。**
7. **不照抄参考的数值**：尺寸可以取（实物量），噪声、`P0`、转速初值必须本机定。

## 11. 保留的问题（阶段 1/2 实机结果）

以下都是 2026-10-17 实机跑出来的、**尚未解决**的现象，先记录，不阻塞阶段 3。

### 11.1 近距离重投影误差随距离上升

实拍一块静止板，逐档测得的 PnP 平均重投影误差（`LogReport` 的 `err`）：

| 板距（激光） | 相机 `dist` | `err` | 占板宽比例 |
| --- | --- | --- | --- |
| 0.599 m | 0.538 m | 2.16 px | 0.5% |
| 0.562 m | 0.611 m | 1.72 px | 0.4% |
| 0.542 m | 0.542 m | 3.08 px（虚焦） | 0.7% |
| 0.406 m | 0.444 m | 3.80 px | 0.7% |
| 0.243 m | 0.276 m | 14.7 px | 1.7% |
| 0.28 m | 0.337 m | 12.2 px | 1.7% |

**已排除的：**
- **PnP 代码本身**。合成自检在 0.3 / 0.4 / 0.5 / 1.0 / 2.0 m 五个距离都落在浮点地板（1e-5 px 量级），0.3 m 处为 1.03e-05 px，完全不随距离上升。所以物点、单位、坐标系、**畸变**（`SOLVEPNP_IPPE` 确实吃进了畸变系数）都没问题。
- **对焦**。同一个距离（0.542 m）虚焦 `err` 3.08 px、对焦 2.16 px，差 0.9 px；解释不了近距离的 12–15 px。

**剩下的判断**：近处板在画面里更大，角点定位误差的绝对值随之放大（左右灯条长度差约 9 px），所以 `err` 随距离上升。这是**网络角点的定位误差**，不是解算误差。

**影响面**：距离估计靠四点整体尺度，对此不敏感（差分核对 40→30 cm 误差 1.0%）；受影响的**姿态角**。跨帧跟踪的观测模型正是"把状态投成像素四点"，所以这个角点误差会在阶段 3 里表现为观测噪声，必须先量化再定后续。

**待验的量化手段**：把同一个静止板在固定距离拍 N 帧，统计四点的帧间标准差（`σ_w`）。若 `σ_w` 与距离成正比、比例系数在 1% 量级，则本现象就被解释为"角点相对误差恒定"，可以直接进阶段 3 的观测噪声模型。

### 11.2 绝对尺度未定

激光测距与相机 `dist` 的差在三个点上是 33 / 38 / 49 mm，**不是常数**（若只是光心比激光前端靠后一个固定距离，它应当是常数）。所以这组激光读数里混了别的误差（板倾角、瞄准点偏离板心、激光打到凸出的灯条），**不能拿它反推物点尺寸 `W`**。

**已被数据支持的两条**（所以 `W` 保持 135 mm、`L` 保持 56 mm 不动）：
- 宽高比：两块数据算得 2.45 / 2.46，`135/56 = 2.41`，差 1.5–2%。若四点缩到内侧，比例会明显偏离。
- 四点位置：目视确认压在两灯条外沿端部附近（非内侧角）。

**唯一能定尺度的干净测法（消掉参考点）**：板放好读一次 `dist`，沿光轴平移一段**用尺子量准的 Δ**，再读一次，比 `|Δ相机 − Δ尺子| / Δ尺子`。判据 ≤ 3%。未测之前不动配置。

**已舍去的数据**：0.599 m 那一组（相机 `dist` 0.538 m）与全部其它组矛盾——它是唯一"相机比激光**低**"的点（−61 mm，其余全是偏高），反推出来的点距 150 mm 也孤立。判断是测量问题（激光瞄点或板朝向不是同一条件），**不再用于任何结论**。

### 11.3 阶段 2 的验收线未达到

文档 §7 阶段 2 定的实拍门槛是 `err ≤ 2 px`，实测 1.7–14.7 px（见 §11.1 表），**只有最远的两次过线**。这个 2 px 当时是参照"标定残差 0.1 px + 假设角点 1 px"定的，而参考自己给检测四点设的噪声是 8 px（`temp/Dust_infantry_vision-main/io/configs/standard3.yaml` 的 `armor_association.image_observation.point_sigma_px` 与 `pnp_observation.point_sigma_px` 都是 8.0）。**所以门槛大概率定错了，但需要用 §11.1 的 `σ_w` 实测来重定，不能凭参考的数字改。**

### 11.4 精修器从未编入

`DUST_VISION_YOLO_REFINER` 在 `framework/algorithm/Kconfig:41` 定义为 `default n`，但 **`project/Kconfig` 里没有任何符号 `select` 它**，所以 `trd_vision.cpp` 中那段 `ArmorRefiner` 调用是死代码，从未执行过。精修器做的正是"把粗四点收拢到灯条端点"，与 §11.1 的角点定位误差可能是同一个解药。**待定：是否在 `TRD_VISION` 里 `select DUST_VISION_YOLO_REFINER`，看开启后 `err` 是否下降。** 未做实验前不动开关。

### 11.5 采集帧率被 USB 2.0 限制

实机 `fps == 24.1`，配置 `frame_rate: 30`。`dropped` 恒定不涨（一直 5），说明不是识别慢丢帧，而是**相机只出约 25 fps**。原因：相机接在 USB 2.0 上，链路带宽限住了——1440×1080 Bayer8 在 USB3 上约 250 Hz、USB2 约 24 Hz（`trd_camera.yaml` 里 `frame_rate` 的注释已写明这个量级），24.1 fps 正是 USB2 的上限。**属于硬件环境限制，不是代码问题**；要提帧率得换 USB3 口/线。

### 11.6 未读配置项

`armor_radius_init_m` 与 `armor_num` 已在 `trd_vision.yaml` 登记进 `LoadVisionConfig` 的可选字段表，但**目前没有消费者**（`trd_vision.cpp` 只读了三个尺寸键）。它们是阶段 4 跟踪器要用的初值，现在是无害的死配置。

### 11.3 记录方式

以上两个问题都**不影响阶段 3 的开工**（跟踪器是纯离线验的，见阶段 3），但会影响阶段 4 的实机验收数字。阶段 4 之前需要先把 11.1 的 `σ_w` 量出来。

## 12. 完成定义

- 合成自检通过：物点反解的 `tvec` 误差 < 1e-3 m、重投影 < 1e-3 px；
- 绝对距离核对通过：1.0/2.0/3.0 m 三档的 `‖tvec‖` 相对误差 ≤ 3%（防双解歧义）；
- 实拍重投影 ≤ 2 px 且四点目视贴合（1 m 外；近距离另按 §11.1 分档）；
- 跟踪器离线验收：合成序列上半径收敛到真值 ±10%、所需帧数 ≤ 17；
- 实机：收敛前只画测到的那块（`state=detecting`），收敛后四面贴合（`state=tracking`）；
- `calib3d` 在只开视觉检测（`TRD_VISION=y` + `TRD_CALIB=n`）时也能被找到；
- `vision_to` 契约不变，`armor_pose` / `armor_tracker` 不读文件、不碰线程。
