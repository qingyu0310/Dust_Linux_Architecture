# 下位机 PDO 协议说明（EtherCAT 从站，双向 256 B）

日期：2026-11-25。读者：从站固件（MCU + HPM EtherCAT ESC）。
对应主站实现：`project/thread/ethercat/pdo_layout.hpp`；主站视角的同一份协议见 `上位机PDO协议说明-2026-11-25.md`。

## 1. 总览

| 项 | 值 |
| --- | --- |
| 方向 | TxPDO（从站 → 主站）/ RxPDO（主站 → 从站） |
| 线上帧长 | 双向各 256 B |
| 从站必须处理的有效区 | TxPDO 前 156 B，RxPDO 前 44 B |
| 周期 | 1 ms |
| 字节序 | 小端（RISC-V 与 x86 均为 LE） |
| 对齐 | 全部 `packed`，1 字节对齐、无填充 |
| 浮点 | IEEE-754 binary32 |
| 版本 | `proto_major=1`，`proto_minor=0`，`slot_map_version=2` |
| 其余字节 | 156 B 之后（Tx）/ 44 B 之后（Rx）不使用，保持 0 |

**硬性要求**：`slot_map_version` 必须是 2。主站按本文偏移组帧；从站按不同偏移解析会直接错位。

## 2. TxPDO：从站 → 主站（你每 1 ms 填）

| 偏移 | 内容 | 字节 |
| ---: | --- | ---: |
| 0 | FeedbackHeader | 30 |
| 30 | RemoteFeedback | 28 |
| 58 | ImuFeedback | 50 |
| 108 | 电机反馈（4 槽 × 12 B） | 48 |
| 156 | 不使用，保持 0 | 100 |

### 2.1 FeedbackHeader（偏移 0，30 B）

| 偏移 | 字段 | 类型 | 从站要求 |
| ---: | --- | --- | --- |
| 0 | magic | u32 | 固定 `0x31424450`（"PDB1"，小端字节为 `50 44 42 31`） |
| 4 | proto_major | u16 | 1 |
| 6 | proto_minor | u16 | 0 |
| 8 | mcu_boot_id | u32 | 每次上电重新生成（随机或单调递增），重启后必须变 |
| 12 | feedback_seq | u32 | 每帧 +1，溢出回绕 |
| 16 | mcu_tick_us | u32 | **本帧组帧时刻**的 MCU 本地 µs 计数 |
| 20 | applied_command_seq | u32 | 最近一次实际执行的 `command_seq`；无执行器时写 0 |
| 24 | accepted_host_session | u16 | 当前被接纳的主机会话号；没接纳写 0 |
| 26 | status_flags | u16 | bit0：已接纳会话（与 `accepted_host_session != 0` 一致） |
| 28 | fault_code | u16 | 故障码；正常写 0 |

### 2.2 RemoteFeedback（偏移 30，28 B）

| 偏移 | 字段 | 类型 | 从站要求 |
| ---: | --- | --- | --- |
| 30 | source_seq | u32 | 遥控接收帧序号，每解析一帧 +1 |
| 34 | sample_tick_us | u32 | 该帧的**采样时刻**（MCU 本地 µs），不是组帧时刻 |
| 38 | axis[0] | f32 | chassisx，归一化 [-1, 1] |
| 42 | axis[1] | f32 | chassisy，归一化 [-1, 1] |
| 46 | axis[2] | f32 | yaw，归一化 [-1, 1] |
| 50 | axis[3] | f32 | pitch，归一化 [-1, 1] |
| 54 | controls | u16 | 开关位：bit0 总开关，bit1 Spin，bit2~bit10 其余开关 |
| 56 | protocol | u8 | 0 = 未报告 |
| 57 | status | u8 | bit0：收到过有效遥控帧 |

### 2.3 ImuFeedback（偏移 58，50 B）

| 偏移 | 字段 | 类型 | 从站要求 |
| ---: | --- | --- | --- |
| 58 | source_seq | u32 | 姿态解算帧序号，每解算一帧 +1 |
| 62 | sample_tick_us | u32 | 该帧采样时刻（MCU 本地 µs） |
| 66 | quaternion[0..3] | f32 ×4 | w, x, y, z |
| 82 | gyro[0..2] | f32 ×3 | rad/s |
| 94 | accel[0..2] | f32 ×3 | m/s² |
| 106 | flags | u16 | bit0：已产生过姿态 |

静态零偏与安装轴在从站侧处理完再上报，主站不重复处理。

### 2.4 电机反馈（偏移 108，48 B）

4 槽 × 12 B，槽位 0~3 依次对应 CAN ID `0x201`~`0x204`。

| 槽内偏移 | 字段 | 类型 | 从站要求 |
| ---: | --- | --- | --- |
| 0 | id | u16 | 槽位号 0..3 |
| 2 | status | u16 | bit0=在线；bit1=故障 |
| 4 | omega | f32 | 轮角速度 rad/s（已按减速比换算到轮侧） |
| 8 | current | f32 | 实际电流 A |

换算：`omega = rpm × 2π / 60 ÷ 减速比`；`current(A) = 原始值 ÷ 819.2`（C620 反馈字节 4~5 的 int16，小端）。

## 3. RxPDO：主站 → 从站（你每帧解析）

| 偏移 | 内容 | 字节 |
| ---: | --- | ---: |
| 0 | CommandHeader | 36 |
| 36 | 电机命令（C620 电流帧数据段） | 8 |
| 44 | 不使用，忽略 | 212 |

### 3.1 CommandHeader（偏移 0，36 B）

| 偏移 | 字段 | 类型 | 从站校验 |
| ---: | --- | --- | --- |
| 0 | magic | u32 | 必须 `0x31434D43`（"CMC1"），否则整帧拒绝 |
| 4 | proto_major | u16 | 1 |
| 6 | proto_minor | u16 | 0 |
| 8 | byte_length | u16 | 必须 256 |
| 10 | slot_map_version | u16 | 必须 2，否则整帧拒绝 |
| 12 | host_session | u16 | 主机会话号，非 0 |
| 14 | command_seq | u32 | 只在主站产生新决策时 +1 |
| 18 | mcu_boot_id_echo | u32 | 必须等于从站当前 `mcu_boot_id`，否则拒绝 |
| 22 | feedback_seq_echo | u32 | 主站依据的反馈序号，诊断用 |
| 26 | lease_us | u32 | 命令租约上限（µs），从站可再夹一层 |
| 30 | compute_time_us | u32 | 主站组帧耗时，诊断用 |
| 34 | flags | u16 | bit0 请求 arm；bit1 请求 disarm |

### 3.2 电机命令（偏移 36，8 B）

主站写入的 C620 电流控制帧（CAN `0x200`）数据段：`u8[8]` = 4 × int16 小端，依次对应 `0x201`~`0x204` 的目标电流。

从站收到后**原样转发**到 CAN `0x200`，不要重新换算。主站未启用控制时该区为全零（零电流）；命令停更 100 ms 后主站也会把它清零。

### 3.3 接收规则

1. 只有新帧才处理：SM2 收帧计数变化视为新命令，重复读同一帧不刷新时间戳。
2. 整帧拒绝条件（任一不满足）：`magic` 错、`byte_length != 256`、`slot_map_version != 2`、`mcu_boot_id_echo` 与当前 boot id 不符、未处于 OP。
3. 通过后：`accepted_host_session = host_session`，记录 `command_seq` 与接收时刻。
4. 掉 OP 或超过 100 ms 无新帧：`accepted_host_session = 0`，`status_flags.bit0` 清零，电机输出按零电流处理（全部写 0 的 0x200 帧）。

## 4. 时序与实现要求

- 1 ms 周期内必须完成 TxPDO 填充；用双缓冲/临界区把控制任务的快照交给 PDI，避免组帧过程中被改写。
- `mcu_tick_us`、`sample_tick_us` 都是 32 位 µs 计数，约 71.6 分钟回绕；主站按模差计算，从站不用处理回绕。
- `feedback_seq`、`source_seq`、`command_seq` 都是 32 位回绕计数，只表示"更新"。
- `mcu_boot_id` 在上电初始化时生成一次，运行期不变。
- 电机反馈/命令槽位固定 4 个，槽位号与 CAN ID 一一对应。

## 5. 自检清单

- [ ] TxPDO 偏移 0 的 magic = `0x31424450`，RxPDO 校验 offset 0 = `0x31434D43`
- [ ] TxPDO 每帧 `feedback_seq` +1，`mcu_tick_us` 为当前 µs
- [ ] 首次运行生成新的 `mcu_boot_id`，并正确回显校验
- [ ] `slot_map_version` 写死 2
- [ ] RxPDO 电机命令原样转发到 CAN `0x200`，字节序不做转换
- [ ] 0x201~0x204 反馈换算成轮侧 rad/s 与实际电流 A 填入槽位
- [ ] 100 ms 无新命令时清 `accepted_host_session` 并输出零电流
