# 多目标跟踪与关联规划

日期：2026-10-17。

对象：在已落地的单目标跟踪器（`algorithm::vision::ArmorTracker`，11 维云台系状态）外面加一层**多目标管理**。3v3 表示敌方最多 3 辆，且型号/编号在编译期就是确定的，所以**跟踪槽位与编号一一绑定、写在 `multi_target.hpp` 里**：每帧按检测的编号直接路由到对应槽，槽内再按几何定面。不做代价矩阵、不做贪心配对、不做生灭。

状态：**规划，尚未动手。**当前 `trd_vision.cpp` 里只有"逐块解 PnP 画轮廓"，跟踪器一次都没接进运行链；跟踪器内部固定把观测当第 0 面。

**自己算出来的量（验收线用它们定）：**

**Q1. 面序判别余量——本规划最关键的一个数。**

四个面在**方位角**上固定相差 90°。相邻两面的预测中心 3D 间距：

```text
d_adj = r·|n_i − n_j|,  n_i = (cos a, 0, sin a),  n_j = (cos(a+90°), 0, sin(a+90°))
|n_i − n_j| = √2  →  d_adj = √2·r
对面差 180°：d_opp = 2r
```

取 `r = 0.2 m`，投影 `x_px = d·f/z`、`f = 1800`：

| 面距 | 3D 间距 | z=1 m | z=3 m | z=5 m |
| --- | --- | --- | --- | --- |
| 相邻（90°） | 0.283 m | 509 px | **170 px** | 102 px |
| 对面（180°） | 0.400 m | 720 px | **240 px** | 144 px |

正确面的残差 ≈ 点噪声（2~8 px），错误面 ≥ 170 px（3 m），**比值 ≥ 21:1**。面序 argmin 余量充分，不是临界判断。

**Q2. 椭圆（半径差 `l`）的最小可分辨量。**

`l` 造成的面心位移就是 `l` 本身，要超过点噪声需 `l·f/z > σ`：

```text
l_min = σ·z/f
```

| 点噪声 σ | z=1 m | z=3 m |
| --- | --- | --- |
| 8 px（参考值） | 4.4 mm | **13.3 mm** |
| 2 px（本机实测 1 m 外） | 1.1 mm | 3.3 mm |

**3 m 处、σ=8 px 时，半径差小于约 13 mm 的"椭圆"与正圆单帧不可分辨。** 多帧累积把门限按 `1/√N` 压低（N=24 → 2.7 mm）。普通车四面同圆、`l ≈ 0`，本就落在此门限之下——所以**画成正圆不是妥协，是模型正确收敛**。

**Q3. `l` 的收敛帧数。**

`l` 要可观测，必须见过**相邻两个面**，即转角跨过 90°：

```text
Δa ≥ π/2 = 1.571 rad
ω = 2 rad/s → 0.785 s → 30 fps → 23.6 帧
```

约 **24 帧**。比半径收敛（15 帧、57°）更慢：多一个待估量，多一段角度。

**Q4. 编号路由的错配代价与后备门限。**

编号路由的失效模式是**模型把编号认错**（→ 检测进了错误的槽）。认错后的检测与该槽的预测相距很远：3 m 处两车横向分离 0.5 m → 投影 `0.5×1800/3 = 300 px`。而合法帧间运动只有：

```text
转速 2 rad/s、r = 0.2 m → 切向速度 0.4 m/s → 帧间 13 mm → 3 m 处投影 8 px
```

所以加一道**残差后备门**：路由到的检测若与该槽预测四点的残差 > `route_gate_px`，本帧不更新（只 `predict`）。取 **40 px**：对合法运动有 5× 余量，对错配（300 px 量级）能挡住。两车投影间距小于 2×40 = 80 px（3 m 处横向 < 0.13 m）时会失效——那是极端贴近，记在 §9。

**Q5. 标签边距（可选加固）。**

模型输出只取 argmax，**没有各类概率**（`ArgMax(row+13, 9)`）。若把 top-1 与 top-2 的差暴露出来，就能在边距过小时拒绝路由。当前拿不到这个数，先不做，列在 §10。

**Q6. 规模。**

3 个槽 × 4 个面 = 每帧 12 次投影，与检测数无关。无代价矩阵、无配对、无生灭。

## 4. 方法学约束

1. **编号认车、几何认面**：`ArmorLabel` 是机器人编号，同车四面同号，**不能**当"第几面"用（模型就 9 个类）。分面只靠 `Q1` 的残差 argmin。
2. **面序每帧独立算，不许计数**：累加"第几次看到"会因丢帧/配错永久飘一格，且没有真值可纠。argmin 依赖当前帧观测，错一次下一帧自动纠正。
3. **槽位与编号编译期绑定，写在 `multi_target.hpp`**：不做运行时关联。代价是换对手/换编制要重编，收益是没有配对问题、没有生灭管理。
4. **一辆车一帧最多一个面**：四个面里只有正对相机那个可见。所以按编号路由后，每个槽每帧最多一个检测，**槽内不需要再配对**。若同号出现两个检测（模型重复检出），本帧拒绝更新并在日志计数——不要"取第一个"。
5. **配上就 `Update`、不重置**：`r`/`a`/`w` 连续继承，这才是"继续收敛"。槽位常驻，不存在销毁重建。
6. **`l` 是否可估由数据决定，不由代码决定**：正圆车 `l < 13 mm`（`Q2`）本就不可分辨，argmin 会随意取一个面、`l` 收敛到 0——**这是正确行为，不加特判**。
7. **有后备门**：路由到的检测若与预测残差过大，本帧不更新（`Q4`）。拿不准就 `predict`，比错误更新好。
8. **不照抄参考的数值**：参考的 `min_detect_count` / `max_temp_lost_count` 是 165 fps 下的，本工程 30 fps 重定。
9. **不改 `vision_to` 契约**：多目标结果仍只在视觉线程内用于绘制。

## 5. 算法与公式

### 5.1 槽位定义（`multi_target.hpp` 编译期常量）

```cpp
// 3v3：三个固定槽，各绑一个机器人编号。编号即 ArmorLabel。
// 敌人编号与槽序的对应关系写死在这里；换编制就改这张表。
constexpr std::array<ArmorLabel, 3> kTargetLabels = {
    ArmorLabel::One, ArmorLabel::Two, ArmorLabel::Three
};
```

### 5.2 每帧流程

```text
输入：当帧检测列表 armors、时间戳 t、dt

for 每个槽 s:
    tracker[s].Predict(dt)                      // 先推进，无论本帧有无检测

for 每块检测 a（遍历 armors）:
    查 a 的编号在 kTargetLabels 里的槽序 s
    没有对应槽 → 忽略（不是要跟的车，比如哨兵/基地）
    该槽本帧已有检测 → 记为重复，本帧拒绝更新并计数
    否则记下 (s, a)

for 每个拿到了检测的槽 s:
    face = argmin over f∈{0..3} of 重投影残差(tracker[s], f, 该检测四点)
    若 最小残差 > route_gate_px → 本帧不更新（后备门，Q4）
    否则 tracker[s].Update(该四点, size, dimensions, camera, dt, face)   // 继续收敛
```

### 5.3 面序与代价

对槽 `s`、检测 `j`、面 `f`：

```text
residual(s, f, j) = Σ_k ‖project_face(s, f, k) − corners_j[k]‖²    // 四点残差平方和
face(s, j) = argmin_f residual(s, f, j)
```

`project_face(s, f, ·)` 就是把槽 `s` 的状态按第 `f` 面投成四点。这一步需要的量在跟踪器里已具备：

```text
angle  = FaceAngle(state, f) = limit(a + f·2π/4)
radius = (armor_num == 4 && f ∈ {1,3}) ? r + l : r
height = (armor_num == 4 && f ∈ {1,3}) ? cz + h : cz
```

后两项与 `ArmorCenter` 现在的 `use_second` 分支**完全一致**，只差把 `f` 从常量 0 换成参数。

### 5.4 丢帧与恢复

没有状态机、没有生灭。槽位常驻，某帧没有它的检测就只 `predict`：`a += w·dt`，`r`/`l`/`h` 不动。车转回来时观测与预测仍在同一方位附近（`Q1`），`Update` 直接接上，**半径不重收敛**。

唯一要防的是**长时间离线后的错误接续**（车早走了、预测还停在原地）：照参考 `tracker.cpp:527-536`，帧间隔 `dt > 0.3 s` 说明相机跨帧离线，此时把该槽标记为"需重新初始化"，下一次观测直接走 `Initialize` 而不是 `Update`。

### 5.5 `Update` 的面序入参

```cpp
bool Update(corners, size, dimensions, camera, dt_s, std::int32_t face);
```

`Observe()` 内部把写死的 `kObservedFace = 0` 换成传入的 `face`；其余（雅可比对哪几个状态求导、数值差分）不变——`face` 是常量参数，不进状态、不进雅可比。

### 5.6 EKF 的两处改造（取自 `sp_vision_25`）

本工程的 `algorithm::filter::ExtendedKalmanFilter` 是分离式的 `predict(f, F)` / `correct(z, h, H)`，**没有自定义加法与减法**，所以角度归一化只能放在调用侧手动做。`sp_vision_25` 的 EKF 把这两件事收进滤波器内部，值得照抄：

**（a）自定义加法 `x_add` 与减法 `z_subtract`。**

```cpp
// sp_vision_25 tools/extended_kalman_filter.hpp:15-38
using AddFn     = std::function<State(const State&, const State&)>;
using SubFn     = std::function<Measurement(const Measurement&, const Measurement&)>;
// x_add：默认逐元素相加；本工程要额外把角度分量包回 (−π, π]
// z_subtract：默认逐元素相减；像素观测下用默认即可，将来若观测含角度分量则在这里处理最短角差
```

改造后，跟踪器 `Predict()` 里那句"预测完手动 wrap 角度"可以删掉，改成把 wrap 逻辑作为 `x_add` 传进滤波器构造。

**（b）NIS 卡方检验。**

每次 `correct` 后算归一化新息平方 `NIS = yᵀ·S⁻¹·y`（`y` 是残差、`S = HPHᵀ+R`），与卡方阈值比较，滑窗统计失败率：

```text
NIS = yᵀ S⁻¹ y
失败率 = 滑窗内 NIS > 阈值的帧数 / 窗口长度
```

`sp_vision_25` 用"失败率 ≥ 40% 窗口"直接判该目标跟丢（`tracker.cpp`）。本工程当前只有 `Diverged()`（只看半径是否出 `[0.05,0.50]`），**拿不到"残差持续偏大但半径还没出界"这类跟丢**——补上 NIS 就能量化它。

**注意阈值不能照抄**：`sp_vision_25` 的观测是 4 维 `[yaw, pitch, distance, angle]`，阈值按自由度 4 取；本工程的观测是 **8 维像素**（四点各 2），自由度和量纲都不同，阈值必须按本机点噪声重定（`Q2` 的 σ 就是起点）。

## 7. 分步骤

### 阶段 0：跟踪器支持按面观测（只改算法层，不动线程）

**做什么 / 落点：** `armor_tracker.hpp/.cpp`：`Update()` 增 `face` 入参，`Observe()` 用参数替掉 `kObservedFace = 0`，暴露 `ProjectFace()`。

**算法与公式：** §5.5 三条随 `face` 变的量；合法性 `0 ≤ face < armor_num`。

**验收数字：** test 线程的合成自检里让车**跨过 90°**（`Q3` 的 24 帧）后打印 `l`：
- 合成椭圆（`l = 0.05 m`）→ `l` 收敛到真值 **±20%**；
- 合成正圆（`l = 0`）→ `|l| < 13 mm`（`Q2` 的门限）。

**失败分叉：** 椭圆情形 `l` 收敛到 0 → 打印每帧的 `face`，查它有没有真的在变；`l` 跑到钳制边界 → 查 `ArmorCenter` 的 `use_second` 与面序是否同一套约定；正圆情形 `|l|` 超 13 mm → 查是不是把观测喂给了错误的面（面序写成了常量）。

### 阶段 1：多目标层（仍不动运行链）

**做什么 / 落点：** `framework/algorithm/vision/track/multi_target.hpp/.cpp`；Kconfig 加 `DUST_VISION_MULTI_TRACK`；CMake 接入。

**算法与公式：** §5.1 槽表、§5.2 流程、§5.3 面序与代价、§5.4 丢帧路径。

**验收数字：** 合成序列——造**两辆车**（不同位置、不同转速、不同编号）各跑一圈，检测列表按帧混在一起喂进去：

1. 两槽各自半径收敛到真值 **±10%**；
2. **编号路由错配次数 = 0**（每帧记录"第 j 块检测归了哪个槽"，与合成真值比对）；
3. 中途遮住一辆 10 帧不喂它的检测 → 恢复后该槽 `r` 与遮断前之差 **< 5%**（不重收敛）；
4. 合成里混入**第三辆的编号**（不在 `kTargetLabels` 里）→ 被忽略、不影响两槽。

**失败分叉：** 两槽半径互相污染 → 查编号路由是否按 `raw_label_id` 而非别的字段；遮断后半径从初值重收敛 → 查丢帧路径是不是误调了 `Initialize`；恢复后残差巨大被后备门挡住 → 查 `dt` 是否超 0.3 s 被判重新初始化（合成里 dt 固定，应走 `Update`）。

### 阶段 1.5：EKF 补 `x_add` / `z_subtract` 与 NIS 检验（§5.6）

**做什么 / 落点：** `framework/algorithm/filter/kalman/ekf.hpp` 增两个可选函数参数（默认逐元素加减）；`armor_tracker.cpp` 把 `Predict()` 里手动 wrap 角度的代码改成通过 `x_add` 传入；`multi_target` 用 NIS 失败率作跟丢判据。

**算法与公式：** §5.6 的两条。

**验收数字：**
- **改造前后行为一致**：同一组合成序列（阶段 1 的两车序列）跑出来的半径收敛帧数与终值**逐位一致**——`x_add` 只是把角度 wrap 从调用侧挪进滤波器，不该改变数值；
- **NIS 能分开两类场景**：正常跟踪（合成无噪声）的窗口失败率 **< 5%**；人为把观测故意挪偏 100 px 后，失败率 **> 90%**。

**失败分叉：** 改造后收敛帧数变了 → `x_add` 里 wrap 的时机与原来不一致（原来在 `predict` 之后，现在在加法里）；NIS 在正常场景就告警 → 阈值按自由度 4 抄了参考，本工程是 8 维像素观测，要按本机点噪声重定（`Q2` 的 σ）；NIS 在明显偏离时不告警 → 检查 `S = HPHᵀ+R` 里的 `H`/`R` 是否与 `correct` 用的是同一份。

### 阶段 2：接入运行链，画所有槽的四面

**做什么 / 落点：** `trd_vision.cpp` 每帧把 `result.armors` 交给 `MultiTargetTracker::Update()`；取各槽 `Converged()` 的 `Armors()` 四面，各自 `ProjectPose` 后描在发布帧上；未收敛的槽只描"当前观测到的那块"。

**验收数字：** 实机对一辆自转车：收敛后四面贴合，日志该槽 `converged=1`；对一辆正圆车：四面同样贴合（`l` 收敛到近 0）；两辆车同时在画面里：两槽各自收敛、互不干扰。

**失败分叉：** 四面与画面里的板对不上 → 先查 `face` 方位与 `ArmorCenter` 的 `use_second` 是否同一套约定；正圆车画出两个半径 → 查 `shape_variance`（`r/l/h` 的过程噪声）是否比 `Q2` 门限还大；两车互串 → 查 `raw_label_id` 是否被正确路由。

## 8. 顺序为什么不能换

1. **面序（阶段 0）必须先做**：路由后的观测要落到正确的面上，面序写死成 0 时槽内的观测模型是错的，`l` 永远估不出来。
2. **多目标层要离线验完再上实机**：实机上"路由错"和"跟踪器没收敛"混在一起看不出（与 `装甲板位姿与四面绘制规划.md` §8 第 5 条同一理由）。合成两车序列能把两者分开。
3. **丢帧语义要早于运行链**：实机上"车转出视野再转回来"会不会重收敛，取决于这一步是否误调 `Initialize`；逻辑必须先定。
4. **`l` 的验收要在多目标层里重验一次**：单槽能估出 `l`，不代表路由后还能——两处都要过。
5. **`vision_to` 契约不动**：整条链只用现有通道容量，多目标结果暂不外发。

## 9. 失败回退表

| 症状 | 先查 | 再查 | 最后才查 |
| --- | --- | --- | --- |
| 两槽半径互相污染 | 编号路由用的是不是 `raw_label_id` | 后备门是否被绕过（`route_gate_px` 调太大） | 两车投影间距是否 < 80 px（`Q4` 的失效边界） |
| 半径一直收敛不好 | 打印每帧 `face`，看观测是否喂给了错误的面 | `l` 是否被反复激励（正圆车应停在 0） | 初始协方差里 `center`–`r` 的相关项是否还在 |
| `l` 收敛到钳制边界 | `ArmorCenter` 的 `use_second` 与面序约定是否一致 | 合成给的 `l` 是否超过 `Q2` 的可分辨门限 | 点噪声是否被设得过大把 `l` 淹了 |
| 遮断后半径重收敛 | 丢帧路径是否误调了 `Initialize` | `dt > 0.3 s` 是否触发了重新初始化 | `Predict()` 在没观测时是否被调用 |
| 同号出现两个检测 | 检测器是否重复检出（看 `accepted` 与 `nms_kept`） | 是否该收紧 NMS 门限 | 是否需要在多目标层做去重 |
| 正圆车画出两个半径 | `shape_variance` 是否过大把 `l` 推离 0 | 正圆下面序 argmin 是否稳定 | `l` 是否需要在 `\|l\| < Q2 门限` 时钳到 0 |
| 车转回来认不出 | `dt` 是否超过 0.3 s | 该编号的检测是否被后备门挡住 | 编号是否被模型认错（见 Q5 的边距加固） |
| 加 `x_add` 后收敛帧数变了 | `x_add` 里 wrap 的时机（原来在 `predict` 之后） | 角度分量的下标是否仍对得上 | 是否同时改了别的默认值 |
| NIS 正常场景就告警 | 阈值是否照抄了参考的自由度 4 | 本工程是 8 维像素观测，按 `Q2` 的 σ 重定阈值 | `R` 是否与 `correct` 用同一份 |

## 10. 明确不做

1. **不做运行时关联（代价矩阵 / 贪心 / 匈牙利）**：槽与编号编译期绑定，配对问题不存在。
2. **不做生灭管理**：槽位常驻 3 个。
3. **不做状态机 `switching` 与优先级选敌**：只跟踪与绘制。
4. **不做前哨站三面与基地**：`armor_num = 4`。
5. **不做动态 ROI**：不反向缩检测器的搜索范围。
6. **不暴露标签边距（Q5）**：需要改 `ArmorDetector` 的输出读取（除 argmax 外再取 top-2），当前不做；编号认错先靠 `Q4` 的后备门兜。
7. **不改 `vision_to` 契约**：多目标结果暂不外发。
8. **不引入云台姿态**：状态仍在相机系/云台系，没有 `R_gimbal2world`（与 `装甲板位姿与四面绘制规划.md` §10 第 1 条同一理由）。
9. **不为正圆加特判**：`l → 0` 是模型正确收敛的结果（§4 第 6 条）。

## 11. 完成定义

- 单槽跨 90° 后：椭圆合成样本 `l` 收敛到真值 ±20%，正圆样本 `|l| < 13 mm`；
- 两车合成序列：各自半径收敛到 ±10%、编号路由错配 = 0、遮断 10 帧恢复后半径差 < 5%、第三辆车编号被忽略；
- EKF 加 `x_add`/`z_subtract` 前后，同一合成序列的收敛帧数与终值逐位一致；
- NIS 失败率：正常场景 < 5%、观测偏 100 px 时 > 90%；
- 实机单车：收敛后四面贴合；正圆车四面同样贴合；
- 实机双车：两槽各自收敛、互不干扰；
- `track_route_gate_px` 与 NIS 阈值来自 `trd_vision.yaml`；槽位与编号来自 `multi_target.hpp` 的 `kTargetLabels`，不散落在别处；
- `armor_tracker` / `multi_target` 不读文件、不碰线程、不起全局状态。
