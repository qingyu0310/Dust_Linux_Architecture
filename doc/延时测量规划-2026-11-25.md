# 延时测量（上位机打印）

日期：2026-11-25。范围：上位机（Linux + SOEM）在每个 1 ms 周期打印发送/接收耗时。MCU 侧本版无需改动。

## 1. 测什么

| 名称 | 定义 | 时钟 |
| --- | --- | --- |
| 发送耗时 | `ec_send_processdata()` 调用到返回 | 主机 `CLOCK_MONOTONIC` |
| 接收耗时 | `ec_receive_processdata()` 调用到返回 | 同上 |
| 收发往返 | 发送开始 → 接收返回（同一周期） | 同上 |
| 周期 | 相邻两次发送开始的间隔 | 同上 |
| 样本年龄（可选） | `mcu_tick_us − sample_tick_us`（TxPDO 内两个 MCU 时间戳） | MCU |

跨机时钟不相减；以上前四项都在主机单时钟内，直接相减即可。

## 2. 上位机怎么做

### 2.1 初始化

1. `ec_init` + `ec_config_init`，确认从站进 OP。
2. `ec_config_map` 后按协议文档把 `IOmap` 映射成 256 B 的 Rx/Tx 结构体（`packed`）。
3. 读取一次 TxPDO 的 `mcu_boot_id` 与 `proto_major/minor`；`mcu_boot_id` 变化时重新读取。
4. 选非 0 的 `host_session`，之后每帧回显 `mcu_boot_id_echo`。

### 2.2 周期循环

```text
t0 = now()
写 RxPDO（header 全字段 + 预留区清零）
ec_send_processdata()
t1 = now()
ec_receive_processdata(timeout)
t2 = now()

打印:
  cycle_us     = t0 - t_prev0
  send_us      = t1 - t0
  recv_us      = t2 - t1
  roundtrip_us = t2 - t0
  （可选）age_imu_us    = mcu_tick_us - imu.sample_tick_us
  （可选）age_remote_us = mcu_tick_us - remote.sample_tick_us

t_prev0 = t0
clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, t0 + 1ms)
```

实现要点：

- 只用 `CLOCK_MONOTONIC`。
- 绝对时间等待；迟到就跳过本拍并打印 `late=1`，不补发。
- 每周期打印一行，字段固定、单位 µs，便于直接重定向到 CSV：

```text
[ecat] t=123456.789 cycle=1001 send=12 recv=140 roundtrip=152 late=0 wkc=3 al=8
```

- 退出时打印一次汇总：`roundtrip` 的均值 / P50 / P99 / max，`late` 次数，以及样本年龄的 max（如果打印了）。

### 2.3 判读

- `roundtrip_us` 是主站发送到收到同一周期数据的网络往返，正常应在数百 µs 内（取决于主站网卡与调度）。
- `send`/`recv` 各自明显偏大 → 主机侧阻塞（调度、网卡 IRQ、日志写盘）。
- `cycle_us` 偏离 1000 大 → 主机调度抖动或 `late=1` 频繁。
- 若 `mcu_boot_id` 变化：从站重启，之前的数据不连续。

## 3. 可选：端到端命令延时

需要 MCU 回显 `applied_command_seq`（当前恒 0）。回显后上位机可算：

```text
RTT = t_recv(收到回显该 command_seq 的 TxPDO) - t_send(发出该命令)
```

这是"命令发出 → 从站接纳并回传到主机"的完整往返，同样只用主机时钟。本版不做，留作后续。

## 5. 实测记录（2026-11-25）

**环境**：Linux + SOEM，i225 千兆网口，1 个从站；上位机 PDO 协议 v1（双向 256 B），线程周期参数 1 ms（外壳 delay 语义：任务结束后再等 1 ms）。

**数据**（`log on ecat_timing` 逐拍输出，第一段 8 拍）：

```text
t=290.740 cycle=1152 send=9  recv=69  roundtrip=79  late=0 wkc=3/3
t=290.751 cycle=1168 send=9  recv=74  roundtrip=83  late=0 wkc=3/3
t=290.763 cycle=1210 send=17 recv=80  roundtrip=98  late=0 wkc=3/3
t=290.775 cycle=1149 send=9  recv=72  roundtrip=82  late=0 wkc=3/3
t=290.786 cycle=1120 send=1  recv=65  roundtrip=67  late=0 wkc=3/3
t=290.798 cycle=1143 send=10 recv=64  roundtrip=74  late=0 wkc=3/3
t=290.809 cycle=1119 send=8  recv=63  roundtrip=72  late=0 wkc=3/3
t=290.820 cycle=1136 send=10 recv=67  roundtrip=77  late=0 wkc=3/3
```

第二段窗口（35 拍）出现一次 `recv=553` 尖峰，同拍 `roundtrip=554`、下一拍 `cycle=1625`；其余 `recv` 63–93 µs、`send` 1–18 µs、`cycle` 1120–1282 µs。

**汇总**：

| 量 | 实测 |
| --- | --- |
| `cycle` 均值 | ≈ 1150 µs（1119–1282，尖峰后 1625）→ 实际约 870 Hz |
| `send` 均值 | ≈ 9 µs（1–18） |
| `recv` 均值 | ≈ 66–69 µs（63–93；约每 100 ms 一次 550 µs 级尖峰） |
| `roundtrip` 均值 | ≈ 79 µs（66–112） |
| `late` | 0（阈值 2 ms） |
| `wkc` | 3/3 |

**有效数据段速率**：

- 有效数据段 = RxPDO 命令头 48 B + TxPDO 头/遥控/IMU 128 B = **176 B/周期**
- 理论速率（1 ms 标称）：176 × 8 ÷ 1000 µs = **1.408 Mbit/s**
- 实测：176 × 8 ÷ 1150 µs ≈ **1.225 Mbit/s**，占理论 **≈ 87%**
- 占千兆链路：有效段 **0.12%**；完整 512 B PDO **0.36%**

**结论与归因**：

1. 周期偏大约 13%：外壳 `period` 是"任务跑完再等 1 ms"，`cycle` = 1000 + 任务耗时（roundtrip 79 + 日志/发布/解析）≈ 1150 µs，实际控制频率约 870 Hz。要跑满 1 kHz 需要绝对时刻调度（`PeriodMode::Absolute` 规划项，未实施）。
2. `send` 只测"帧交给内核"，`recv` 测"帧绕一圈回来 + 主机中断/唤醒"，所以 `recv` 天然远大于 `send`。65 µs 构成：512 B 线上传输约 5 µs、从站 ESC 转发约 1 µs，其余为网卡中断与用户态唤醒。
3. `recv` 尖峰来源 = 主站自身：`Read()` 每 100 ms 在 `recv` 计时区间内插两次 AL 状态 `ecx_FPRD`（`kStatusPollMs`），再叠主机调度抖动；从站 ESC 硬件转发，MCU 固件处理时长不进入该往返。
